# 실험: 오버레이 + TalkBack 호환 (F10, C 담당)

- 담당: C
- 실험 앱: `experiments/overlay-talkback/` (패키지 `com.team.popup.experiment`, 본 앱과 별개)
- 목적: "닫을까요?" 창을 띄웠을 때 **TalkBack 사용자가 알아차리고, 버튼에 도달하고, 하던 일을 방해받지 않는** 안내 방식을 고른다.

---

## 1. 실험 앱이 하는 일

1. 실험 화면에서 **안내 방식**과 **기다리는 시간**을 고른 뒤 [테스트 팝업 예약하기]를 누른다.
2. 정해진 시간(3/5/10초)이 지나면 화면 아래에 테스트 팝업이 뜬다. 그 사이에 다른 앱으로 이동해서 "하던 작업 중에 팝업이 뜨는 상황"을 만든다.
3. 팝업: 요약 문장 + [닫기] [앞으로 항상 닫기] [그대로 두기]. 어느 버튼이든 누르면 팝업이 닫히고, 실험 화면 "최근 기록"에 남는다.

| 안내 방식 | 동작 |
|---|---|
| (기준) 없음 | 아무 안내도 안 함. TalkBack이 새 창을 스스로 알리는지 보는 비교 기준 |
| (a) paneTitle | Compose `semantics { paneTitle }` + 창 제목(`LayoutParams.title`) 지정 |
| (b) liveRegion | 요약 문장에 `LiveRegionMode.Polite`. 빈 글자로 시작해 0.5초 뒤 문장을 채움 (라이브 영역은 내용이 **바뀔 때** 읽히기 때문) |
| (c) TTS | 앱 자체 `TextToSpeech`(한국어, 접근성 음량)로 요약 문장 낭독. 시작 지연 0 / 700 / 1500밀리초 선택 |

- 화면 내용은 읽지 않는다 (`canRetrieveWindowContent=false`). INTERNET 권한 없음 (병합 매니페스트 확인 완료).
- 팝업 창은 `FLAG_NOT_FOCUSABLE` → 키보드 입력 포커스를 가져가지 않는다. TalkBack 포커스도 코드로 옮기지 않는다 (원칙 7).

---

## 2. 폰에 설치하고 켜기

### 2-1. 개발자 옵션 + USB 디버깅 (처음 한 번)

1. 설정 → 휴대전화 정보 → 소프트웨어 정보 → **빌드번호를 7번** 연속 탭 → "개발자 모드를 켰습니다"
2. 설정 → 개발자 옵션 → **USB 디버깅** 켜기
3. USB로 PC에 연결 → 폰에 뜨는 "USB 디버깅을 허용할까요?"에서 허용

### 2-2. 설치

Android Studio에서 `experiments/overlay-talkback` 폴더를 열고 ▶ Run을 누르거나, 명령줄로 설치한다.

```bash
D:/Android/SDK/platform-tools/adb.exe devices
```

```bash
D:/Android/SDK/platform-tools/adb.exe install -r D:/close_for_you/experiments/overlay-talkback/app/build/outputs/apk/debug/app-debug.apk
```

(APK가 없으면 먼저 `experiments/overlay-talkback` 폴더에서 `gradlew.bat assembleDebug`)

### 2-3. "제한된 설정" 허용 (Android 13 이상)

APK 파일을 직접 받아서 설치한 앱은 접근성 서비스를 켜려고 할 때 **"제한된 설정"** 안내가 뜨며 막힐 수 있다.

1. 설정 → 애플리케이션 → **오버레이 실험** → 오른쪽 위 ⋮ → **제한된 설정 허용**
2. 다시 접근성 설정에서 서비스를 켠다.

> adb나 Android Studio로 설치하면 보통 안 뜬다. 실제로 뜨는지는 S26에서 **확인 필요**.

### 2-4. 실험 서비스 켜기

1. 앱 **오버레이 실험** 실행 → [접근성 설정 열기]
2. 갤럭시: 설정 → 접근성 → **설치된 앱** → **팝업 오버레이 실험** → 켜기 → 허용
3. 앱으로 돌아오면 "실험 서비스: 켜짐"으로 바뀐다.

### 2-5. TalkBack 켜기·끄기

- 설정 → 접근성 → TalkBack → 켜기
- 단축키: **음량 올리기 + 내리기를 3초** 동시에 누르기 (처음엔 설정에서 단축키 허용 필요)
- TalkBack 켜진 상태 조작: 한 번 탭 = 읽기, **두 번 탭 = 누르기**, 오른쪽/왼쪽 쓸어넘기기 = 다음/이전 항목, 두 손가락 = 스크롤

> 팁: 실험 앱 설정은 TalkBack을 끈 상태에서 고르고, 팝업을 예약한 뒤 TalkBack을 켜면 편하다.

## 3. 실험 절차 (방식마다 반복)

1. 실험 앱에서 안내 방식 선택, 기다리는 시간 **5초** → [테스트 팝업 예약하기]
2. 홈으로 나가서 **다른 앱**을 연다 (시나리오 아래 표). TalkBack 포커스를 그 앱의 어떤 항목에 둔다.
3. 팝업이 뜰 때 들리는 것을 기록한다.
4. 쓸어넘기기로 요약 문장 → 버튼 3개에 도달하는지, 순서가 맞는지 확인한다.
5. [닫기]를 두 번 탭해서 닫힌 뒤 TalkBack 포커스가 어디로 가는지 확인한다.

| 시나리오 | 하던 작업 |
|---|---|
| S1 | 홈 화면에서 아이콘 탐색 중 |
| S2 | 메모 앱에서 글자 입력 중 (키보드 열림) |
| S3 | 유튜브 등 영상 재생 중 (소리 겹침 확인) |
| S4 | TalkBack이 긴 글을 읽는 중 (읽기 도중 팝업) |

## 5. 미리 알고 있는 불확실한 점 (실기기 확인 필요)

- `LayoutParams.title`이 접근성 오버레이 창의 TalkBack 안내에 쓰이는지 공식 문서로 확인하지 못함 → (a)에서 같이 확인.
- 라이브 영역이 **새로 뜬 창 안에서** 읽히는지 (보통 "이미 보이는 창의 내용이 바뀔 때" 동작).
- 삼성 TalkBack은 Google 버전을 삼성이 고친 것이라 Pixel과 결과가 다를 수 있음 → 가능하면 Pixel 한 대 추가.
- 자체 TTS는 접근성 음량(`USAGE_ASSISTANCE_ACCESSIBILITY`)을 쓰도록 설정함. TalkBack 낭독과 섞일 때 어떤 게 먼저 나오는지 확인.
- `announceForAccessibility()`는 사용 중단이라 시험 대상에서 뺐다.
- 실험 앱은 팀 앱과 별개인 독립 Gradle 프로젝트다 (AGP 9.2.1 / Gradle 9.4.1, 팀 CI 미포함). 결과만 `ui/voice` 구현에 반영한다.
