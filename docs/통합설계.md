# 닫아줄게 — 통합 설계 v5 (기술·안전성 수정본)

> 기준 문서: `닫아줄게_통합설계_v4.md` (사용자 제공). 2026-10-12 기준으로 검토한 Android/ML Kit 공식 자료와 설계 판단을 **분리**하여 개정했다. **구현·실기기 시험을 수행했다고 주장하지 않는다.**
>
> 목적: TalkBack 사용자가 일반 Android 앱에서 접근하기 어려운 팝업을 **발견 → 내용을 파악 → 종류를 구분 → 안전하게 닫거나 사용자에게 선택권 제공 → 결과 확인**할 수 있도록 한다. 인터넷 보안 과목과의 연관성이나 특정 기종·개발 기간은 기능을 축소하는 기준으로 삼지 않는다.
>
> **표기:** `[확인됨]` 공개 공식 API의 명세로 확인된 내용 · `[설계]` 팀이 선택할 처리 정책 · `[실험 필수]` 대상 기기·앱에서 작동 및 정확도 미검증 · `[기술 한계]` 현재 방식이 보장할 수 없는 것.

## 1. 기능 범위와 절대 원칙

### 1-1. 처리 결과 네 가지

- **자동 닫기:** 명확하고 검증된 닫기 동작만. 사용자가 해당 동작에 사전 동의한 경우.
- **읽고 묻기:** 공지, 처음 본 이미지·영상, 처음 만난 닫기 버튼 등은 내용을 알리고 사용자가 선택.
- **내용/위치 안내:** 텍스트/그림 설명이나 버튼 위치를 알려주되 앱이 누르지는 않음.
- **보호 중단:** 결제·권한·로그인·삭제·민감 또는 판단 불가 화면. 자동 동작 없음.

### 1-2. 불변 원칙

1. **모든 외부 앱 조작은 한 개의 행동 게이트(F8/F9)를 통과한다.** 접근성 노드 클릭·제스처·뒤로 가기 모두 포함.
2. **AI가 광고라고 추측했다고 자동 닫기를 허용하지 않는다.** AI 설명과 자동화 허용은 서로 다른 출력이다.
3. **모르는 팝업은 닫지 않는다.** 미탐지·분류 실패·캡처 실패는 자동 조작 금지로 끝나야 한다.
4. **'닫기', 'X', `ACTION_DISMISS`라는 단서만으로 안전하다고 단정하지 않는다.** 팝업의 맥락·대상·이전 검증을 함께 본다.
5. **민감 화면에서는 캡처와 외부 전송을 최대한 피한다.** 보호 여부를 완벽히 알 수 없다는 한계도 공개한다.
6. **TalkBack 포커스는 사용자가 소유한다.** 요청되지 않은 포커스 이동 금지, 불가피한 복구는 최소화한다.
7. **잘못된 조작의 사후 복구를 보장하지 않는다.** 의심되는 버튼은 클릭 전에 막는다.
8. **허용한 앱과 기종만 실측으로 보장한다.** '모든 앱·모든 팝업'이라고 홍보하지 않는다.
9. **버튼 누름의 성공과 안전성은 다른 지표다.** 팝업 소멸 ≠ 의미 검증.
10. **사용자 명령에도 위험 동작 금지 정책은 적용**한다. '닫아줘'가 '동의/구매/설치'를 대신 승인하지 않는다.

### 1-3. 두 가지 독립 출력

- `display_class`: 광고로 보임 / 공지로 보임 / 사용자 결정 / 알 수 없음. 사용자에게 알릴 설명이다.
- `action_authorization`: 자동 허용 / 확인 필요 / 자동 금지. **사용자가 확인한 안전한 조작 근거**와 최신 화면의 보호 검사로만 결정한다.

## 2. 시스템 아키텍처와 정확한 실행 순서

### 2-1. 권장 모듈

`AccessibilityService(Kotlin)` → `EventCoordinator(F11)` → `PrivacyGate(F0)` → `PopupDetector(F1)` → `CaptureBroker` → `EvidenceExtractor(F2,F3)` → `Image/VideoAnalyzer(F4,F5,F6)` → `Classifier(F7)` → `PolicyEngine(F8)` → `ActionExecutor(F9)` → `Feedback(F10)` → `LocalStore(F12)`; `VoiceCommands(F13)`은 사용자 요청에서 시작한다.

UI·접근성 이벤트 코디네이터, OCR, 모델 추론, 저장, 동작 실행은 **서로 다른 책임**으로 분리한다. 느린 모델 호출을 UI 스레드에서 수행하지 않는다.

### 2-2. 이벤트에서 행동까지

```text
S0  화면/창 이벤트 수신 → 이벤트 중복 제거·출처 불확실성 표시
S1  F0-A: 현재 앱·창·입력칸 보호 검사 → 금지면 종료
S2  F1: 창/덮개/화면 전환/캔버스 후보 탐지 (아직 '광고' 아님)
S3  정보가 부족하고 캡처 허용 시 CaptureBroker가 필요한 화면만 캡처
S4  F0-B: 캡처 후 민감 신호 검사 → 실패·보호 신호면 폐기·중단
S5  F2: 트리·OCR, F3: 버튼 근거, F5: 영상 징후 / F4는 가능한 경우 비동기 분석
S6  F7: 안내 분류와 자동화 후보 근거를 별도로 계산
S7  F12: 같은 앱·팝업·버튼에 대한 사용자 확인/규칙 조회
S8  F8: 금지 우선 행동 결정; 설명용 AI가 미완료면 자동 허용으로 승격하지 않음
S9  실행 직전 재검사: 현재 앱/창/버튼/민감 신호/공지 본문/사용자 조작
S10 F9: 승인된 행동 1회 실행 → 완료/이상/미확인 분류
S11 F10: 간단히 안내. 재청취·직접 선택 가능. 포커스 기본 유지
S12 F12: 개인정보 제외한 결과 기록; 다음 팝업은 새로운 절차로 처리
```

**시각 탐지 예외:** 동일 창 캔버스처럼 이벤트에서 팝업 경계를 읽을 수 없는 경우에는 S2에서 `CaptureBroker`를 요청한다. 해당 캡처도 S1 보호 검사, 앱 허용 설정, F0-B 검사, 폐기 규칙을 거쳐야 한다. **감지용 캡처에 보호 예외를 두지 않는다.**

### 2-3. 신선도/무효화 토큰

각 분석은 `screenVersion`, `windowId`, `packageName`, `popupInstanceId`, `structureDigest`, `contentDigest`, `captureEpoch`로 묶는다.

- **창·앱·구조 변경:** 행동 보류, 분석 무효화.
- **본문·숫자·날짜 변경:** `contentDigest` 변경으로 행동 무효화. 카운트다운처럼 자주 바뀌는 영상 표시는 **행동과 무관한 카운트다운 영역만 따로 분리**하고, 그것이 공지·동의 본문인지 확실하지 않으면 재분석.
- **스크롤·화면 회전·폴더블 접힘:** 버튼 위치와 좌표 무효화 후 재탐색.
- **이벤트 출처 불명확/사용자 터치 중:** 자동 실행 보류.
- **클릭 직전 텍스트 재확인 불가능:** 공지 자동 닫기 금지.

**`AccessibilityNodeInfo.refresh()` 성공만으로 최신 내용을 모두 검증했다고 간주하지 않는다.** 창 정체성·본문·버튼 범위까지 다시 확인한다.

### 2-4. 캡처 관리자 — 통일된 보호 경로

| 유형 | 역할 | 캡처 조건 | 보관 |
|---|---|---|---|
| `STRUCTURE_ONLY` | 창·노드 변화만으로 후보 탐지 | F0-A 통과 | 민감 텍스트 로그 제외 |
| `SINGLE_FRAME` | 이미지 팝업·OCR·버튼 탐지 | 해당 앱에서 화면 분석 허용 + F0-A 통과 | 메모리에서만, F0-B 이후 필요한 최소 시간 |
| `TEMPORAL_FRAMES` | 영상 분석/캔버스 변화 비교 | 사용자가 요청하거나 사전에 명시적으로 허용된 앱에서만; 샘플링 예산 제한 | 제한된 프레임만 메모리, 종료·전환 시 폐기 |
| `CLOUD_READY` | 외부 비전 AI 요청 | 사용자의 **별도 요청과 업로드할 이미지 확인** + 전송 금지 검사 | 전송 후 즉시 메모리 해제; 서버 정책 고지 |

- **기본값은 전역 화면 롤링 캡처 꺼짐.** 이벤트 발생 후 분석 가능한 화면만 단발 캡처하며, 이전 프레임이 없으면 전후 비교가 아닌 **단일 프레임 특징**만 사용한다.
- 전후 비교가 정말 필요한 캔버스 앱에서는 **사용자가 지정한 앱에 대해서만** 제한된 비교 버퍼를 허용한다. 앱 전환·민감 의심·서비스 일시정지 시 이전 프레임 즉시 폐기.
- Android 11/API 30+ `takeScreenshot()`, Android 14/API 34+ `takeScreenshotOfWindow()` 사용 가능. 캡처 가능성은 접근성 서비스 메타데이터의 `canTakeScreenshot`, 시스템 정책, 기기 조건의 영향을 받는다. 성공을 보장하지 않는다.
- `FLAG_SECURE` 화면은 우회 대상으로 삼지 않는다. 오류·검은 화면·보호 신호를 받으면 분석 중단. 접근성 도구에 대한 배포 정책상의 예외는 스크린샷 API의 만능 우회 기능이 아니다.
- 캡처 오류/간격 제한에서 연속 재시도를 수행하지 않는다. 정해진 예산과 백오프 뒤 중단.
- 이미지 축소만으로 비식별화가 되지 않는다. 저해상도 프레임도 화면 개인정보이므로 보호 데이터와 동일하게 관리한다.

## 3. 행동 결정표 — 모든 클릭의 단일 관문

### 3-1. 사용자에게 보이는 버튼 등급

| 등급 | 예시 | 의미 | 자동 조작 |
|---|---|---|---|
| C | 닫기, Close | 화면을 닫는 것으로 확인된 후보 | 추가 검증 뒤 조건부 허용 |
| K | 오늘 하루 보지 않기, 취소, 거절, 나중에 | 설정/선택의 의미가 달라질 수 있음 | 기본 금지, 사용자가 확인 |
| S | 건너뛰기, Skip | 광고 스킵 후보 | 사용자 자동 스킵 설정 + 검증된 경우 |
| O | 확인, OK, 알겠어요 | 승인일 수도 단순 확인일 수도 있음 | **기본 자동 금지**; 반복되는 명확한 비결정적 공지에만 사용자 확인 후 검토 |
| D | 동의, 구매, 결제, 삭제, 권한 허용, 로그인, 가입, 구독, 체험 등 | 사용자 결정·상태 변경 | 절대 자동 실행 안 함 |
| P | 설치, 자세히, 받기, 웹 열기 | 이동/실행 유도 | 누르지 않음 |
| U | 의미 불명, 사전 미등록 | 안전성 불명 | 누르지 않음 |
| L | 라벨 없는 버튼 | 시각적 의미 검증 필요 | F3 E3/E4 규칙만 |

**문구 사전은 차단 신호이며 완벽한 의미 인식기가 아니다.** '취소'처럼 문맥에 따라 중대한 결과가 가능한 단어는 자동으로 누르지 않는다. D 단어가 **본문에 단순히 인용**됐다는 사실만으로 결제창이라고 확정하지 않되, 자동 실행은 보수적으로 차단하고 별도 검증한다.

### 3-2. 닫기 후보의 증거 수준 — 기존 E1~E4 유지

| 등급 | 탐색 방법 | 기본 정책 |
|---|---|---|
| E1 | 팝업 노드가 `ACTION_DISMISS` 제공 | 실제 동작·문맥을 확인한 화면에서만 자동 후보 |
| E2 | 접근성 노드에 닫기/스킵 설명과 클릭 동작 존재 | 명확한 버튼이면 자동 후보 |
| E3 | 이름 없는 클릭 노드 + 별도 X 아이콘 탐지 + 사용자 의미 확인 | 반복 화면 바인딩 조건이 맞을 때 자동 후보 |
| E4 | 접근성 클릭 노드 없음, 화면 픽셀상 X만 탐지 | **자동 금지**. 요청 시에도 실제 TalkBack 제스처 호환성 검증·사용자 확인 후 단발 시도 |

E1은 `ACTION_DISMISS`가 노출됐다는 기술적 근거이지, 누르면 정보 손실이 없다는 뜻이 아니다. E3는 아이콘 형태만으로 닫기라고 보장하지 않는다. E4의 '사용자가 두 번 탭' 안내는 해당 요소가 탐색 가능한 경우에만 유효하다.

### 3-3. 판단 우선순위

**먼저 금지:** 민감 앱/화면, 결제·권한·로그인 등 중요 결정, 내용 변경, 대상 버튼 미확인, 사용자 조작 중, 실행 기록 있음, 정책 차단, AI 오류/시간 초과 때문에 안전 근거 미확보, 의심되는 창 전환, 캡처 보호 실패.

**그다음 자동 허용 조건(모두 만족해야 함):**

1. 앱 사용자가 해당 앱의 자동 닫기를 켬. 새로운 광고나 공지를 전부 무조건 누르는 권한은 아님.
2. 현재 화면의 중요한 결정 신호가 없음. 불확실하면 **확인 필요**.
3. 자동 동작이 허용된 **정확한 팝업·버튼 유형**이며, 대상이 E1/E2 또는 명시적으로 바인딩된 E3.
4. **광고(시각)의 경우 미확인 최초 화면에서는 자동 금지.** 수동으로 실제 닫기를 확인한 반복 화면에만 자동화 규칙 생성 가능. 광고 같은 시각 특징 2개만으로 자동화 불가.
5. 사용자 규칙이 현재 패키지·팝업 본문/구조·버튼 서술자·행동 의미까지 일치함. 내용에 중요한 변화가 있으면 규칙 무효.
6. 현재 화면/텍스트/대상 위치를 클릭 직전에 다시 읽을 수 있음.
7. 같은 팝업 인스턴스에 대해서 자동 동작을 실행한 적 없음. 이전 오류로 차단기가 걸려 있지 않음.

**판단 불가에서 '항상 닫기'를 설정하는 경우:** 최초 화면에서 맥락과 버튼 행동을 **사용자가 직접 확인**한 경우에만 패키지·정확한 본문/구조·버튼에 결박. '모든 판단 불가 팝업 닫기'처럼 포괄적 적용 금지.

### 3-4. E3 라벨 없는 버튼 바인딩

**생성:** (a) 사용자가 직접 실행을 요청했고, (b) 팝업 소멸+동일 앱 복귀가 관측됐으며, (c) **사용자에게 '이 버튼이 원하던 닫기였나요?'라고 별도로 확인**, (d) 중요 결정 화면이 아니며, (e) '같은 화면이면 다음부터 자동 닫기'에 명시 동의, (f) 팝업 및 대상 특징을 저장하는 경우. 반복 성공 횟수(예: 2회)는 실험값이지 안전성의 증거가 아니다.

**재사용:** 같은 패키지, 팝업 구조+중요 본문, 노드 클래스/ID/경로/상대 위치, 아이콘 특징, 사용자 허락 및 만료 조건이 모두 일치해야 함. **앱 화면이나 중요한 숫자·행동 문구가 달라지면 재확인.** 재사용에 실패하면 규칙 삭제·일시정지.

**기억으로 자동 클릭할 때도** 현재 화면의 입력칸/결정 단어/보호 게이트는 매번 검사한다.

### 3-5. 사용자 명령의 범위

- `닫아`: 가장 안전한 닫기 후보를 안내하고, **사용자 명령으로 승인된 닫기 후보에 한해** 1회 실행. 불명확하면 버튼 후보만 설명.
- `건너뛰어`: 확인된 S 후보만. 설치/구매/동의 버튼으로 대체 금지.
- `내용 읽어줘` / `그림 설명`: 누르지 않고 정보 안내.
- `돌아가`: 자동 뒤로 가기 금지. 사용자가 요청했고 현재 창이 직전 오류 이동과 일치할 때만 1회 시도; 이전 화면 복귀 보장하지 않음.
- `버튼으로 이동`: 접근성 노드가 있을 때만 포커스 안내. 없는 버튼으로는 포커스를 옮길 수 없다고 안내.
- F0-A 보호 화면에서는 조작 요청을 실행하지 않음. F0-B 민감 화면에서 클릭도 **기본 금지**(v4의 C/E1 명령 예외 제거); 사용자가 직접 원래 앱을 조작하도록 안내.

## 4. F0~F13 기능별 최종 구현 규칙

### F0. 민감 화면 보호

- **목적:** 다른 앱의 비밀번호·금융·건강·메신저·개인정보 내용을 실수로 저장·전송하거나 잘못 클릭하지 않음.
- **구현:** 앱/패키지별 차단 목록(사용자 수정 가능), `isPassword`, 시스템 권한 UI 식별, 입력칸 단서의 F0-A, 허용된 캡처 후 OCR·민감 서식·보안 키패드 징후의 F0-B. 진단 로그는 원문 없이 원인 코드만 남김.
- **규칙:** 기본적으로 금융·메신저·사진·건강·로그인/결제 관련 앱의 화면 분석 금지(설정에서 사용자 선택 조정 가능하나 비밀번호/권한 승인 자동 실행은 영구 금지). F0-A 판단 불가 + 민감 가능성 높음이면 캡처 중단.
- **실패/한계:** 이미지로만 만든 개인정보 화면은 완벽히 검출할 수 없음. '보호 검사 통과'가 비민감 화면의 확정 증명은 아님.
- **검증:** 보호 화면 누락률, 개인정보 포함 캡처/로그/전송 건수, 정상 팝업 잘못 차단한 비율.

### F1. 팝업 감지

- **목적:** TalkBack이 탐색할 수 없는 팝업도 존재를 알아냄.
- **구현:** `getWindows()`와 창 종류/전후 변화, 트리에서 새로운 덮개 및 배경 가림, WebView 노드, 허용된 앱의 단발 캡처에서 화면 중심 덮개/우측 상단 아이콘·배경 어두워짐 등 후보 특징. 게임/캔버스는 단일 프레임+선택적 제한된 전후 비교.
- **규칙:** 발견 결과는 `popup_candidate`일 뿐 광고 판정/자동 클릭 허가가 아님. 작은 팝업도 감지. 키보드·토스트·화면 전환 등 오탐 구분. 표지 없는 Activity 전환을 즉시 버리지 않고 **캡처 허용 여부에 따라 후보 검토 또는 '내용 알 수 없음' 처리**.
- **실패/한계:** 접근성 이벤트가 전혀 오지 않거나 화면을 캡처할 수 없는 앱에서는 자동 감지가 불가능할 수 있음. 지속 스크린샷 감시는 기본값으로 사용하지 않음.
- **검증:** 별도 창/같은 창/전면 이미지/WebView/게임별 정밀도·재현율·지연·오탐.

### F2. 글자 추출 및 근거 결합

- **목적:** 팝업 원문·버튼 글자·위치를 확보함.
- **구현:** 먼저 `getText`, `getContentDescription`, `getViewIdResourceName`, `getBoundsInScreen`; 부족하면 허용된 `SINGLE_FRAME`에서 ML Kit Text Recognition v2 한국어 OCR.
- **규칙:** 각 텍스트는 `source=tree|ocr`, 위치, 신뢰도/품질 표시와 함께 전달. OCR이 찾은 글자를 원본으로 단정하지 않음. 변경된 텍스트를 기준으로 토큰 재검사.
- **실패:** 저해상도·움직임·반사·특수 글꼴, 시스템 캡처 금지. 실패 시 '내용 일부를 읽지 못함' 안내하고 자동 처리 제한.
- **검증:** CER, 중요 날짜·금액·동의 문구 누락, 위치 오차, 처리 지연.

### F3. 라벨 없는 버튼 후보

- **목적:** 라벨 없는 X·건너뛰기 버튼을 식별하되 가짜 버튼을 누르지 않음.
- **구현:** E1 `ACTION_DISMISS` → E2 라벨 있는 클릭 노드 → E3 클릭 노드+아이콘 탐지(OpenCV/객체 탐지) → E4 이미지상 아이콘 후보. OCR은 **텍스트**에만 사용.
- **규칙:** 동작은 F8에서만. E3는 사용자가 의미를 확인한 정확한 반복 화면에 한해 자동 후보. E4는 기본 자동 불가, 사용자 명령도 실제 기기 호환 실험 통과 후만 허용.
- **실패:** 장식용 X, 캔버스 버튼, 좌표 변화, TalkBack 터치 탐색이 제스처에 개입. 후보만 안내해 사용자가 직접 조작하도록 함.
- **검증:** 탐지/오탐/오클릭률, 포커스 없는 버튼 접근 성공률, 기존 TalkBack 대비 조작 수.

### F4. 이미지 의미 설명 — 핵심 기술 교체

- **목적:** 글자가 없는 포스터·그림·아이콘 팝업의 의미를 사용자에게 설명함.
- **현재 확인된 플랫폼 제약:** ML Kit GenAI(Image Description/Prompt 포함)는 앱이 **최상위 포그라운드에 있을 때만 추론 허용**. 접근성 서비스 또는 포그라운드 서비스가 다른 앱 뒤에서 호출하면 `BACKGROUND_USE_BLOCKED`가 발생할 수 있음. 기기 지원 검사만으로 해결되지 않음. `[확인됨]` Google ML Kit GenAI 개요·오류 코드.
- **선택 경로 A — 원래 앱 위에서 자동 설명:** 앱에 포함한 이미지-텍스트 추론 모델(LiteRT/TFLite 또는 별도 런타임)을 **백그라운드 접근성 서비스 경로에서 동작하는지 실기기 시험**한 다음 채택. 모델 구조, 한국어 생성 능력, 메모리·열·성능은 별도 실험. 이미지 분류/라벨링 모델은 상세 문장 설명으로 홍보하지 않음.
- **선택 경로 B — 사용자 요청 후 닫아줄게 화면으로 전환:** 사용자에게 원래 앱의 중단을 고지하고 자체 Activity를 전면에 띄워 ML Kit GenAI를 호출. 지원 여부·모델 설치·실제 추론 오류 확인, 원래 앱으로 돌아가는 사용성 검증. **무단으로 앱을 전환하지 않음.**
- **선택 경로 C — 설명 모델 없음:** OCR과 탐지된 일반 물체 라벨만 안내하고 '그림 전체의 의미는 설명할 수 없음' 명시. 별도 사용자가 요청한 클라우드 경로는 5장의 개인정보 검사 적용.
- **규칙:** AI가 생성한 설명은 '자동 설명, 틀릴 수 있음' 표시; 행동 판단을 높이는 근거로 사용 금지. 오해 위험이 있다면 자동화는 보수적으로 중단.
- **검증:** 지원 기기/배경 실행 여부, 이미지 핵심정보 일치, 없는 내용 비율, 한국어 품질, 실시간 반응, 사용자 이해도.

### F5. 영상 광고 인식 및 스킵

- **목적:** 영상 광고의 건너뛰기/닫기 버튼을 알려주고 처리.
- **구현:** 영상 표면(`VideoView/SurfaceView/TextureView`가 보이는 경우), 허용된 프레임 변화, 광고 관련 접근성 근거, 카운트다운 텍스트를 **서로 다른 신호로** 수집. `AudioManager.isMusicActive()`로 광고인지 판단하지 않음.
- **규칙:** 영상임만 확인되면 '영상 창'이라고 알리고 사용자가 F6 설명·F3 버튼 찾기를 요청 가능. 광고로 확인되고 안전한 닫기/스킵이 식별될 때만 F8. 카운트다운을 실제 읽은 때만 안내. 전체 미디어 볼륨 변경은 기본 끔; 사용자가 켰다면 변경한 값을 추적하고 사용자 변경 시 복원 충돌 방지.
- **실패:** 앱이 영상 정보를 숨기거나 보안 캡처를 사용. 광고임을 알 수 없으면 무리하게 광고로 분류하지 않음.
- **검증:** 영상 탐지/광고 분류 성능 분리, 스킵 성공/잘못된 스킵/대기 시간, TalkBack 음성과의 충돌.

### F6. 영상 내용 설명

- **목적:** 요청했을 때 영상의 일부 시각 정보와 자막·허용되는 음성을 설명.
- **구현:** 사용자 요청 → 제한된 `TEMPORAL_FRAMES` → 장면 대표 프레임 → 프레임별 F0-B/OCR/F4 **실제로 사용 가능한 경로** → 시간순 텍스트 정리. 오디오는 사용자 별도 권한·MediaProjection 동의 및 재생 앱의 캡처 허용이 필요할 수 있음.
- **규칙:** 각 프레임의 분리된 설명을 시간순으로 전달. **시간상 원인·결과, 영상 전체의 목적을 추측해서 사실처럼 말하지 않음.** 일부 프레임만 볼 수 있으면 '일부 장면'이라고 안내.
- **실패:** 장면 사이 중요한 정보 누락·녹음 차단·과열/지연. 실패한 입력은 미확인 표시.
- **검증:** 핵심 항목, 장면 순서, 허구 비율, 누락률, 지연, 배터리 및 사용자 이해도.

### F7. 팝업 유형 분류 — 보이는 정보와 자동화 증거 분리

- **표시 분류:** 광고로 보임 / 공지로 보임 / 결정 필요 / 불확실.
- **자동화 증거:** (a) 공식 접근성 노드에서 광고/닫기 컨텍스트 확인, (b) 정확히 일치하는 사용자 검증 반복 패턴, (c) 버튼 행동 안전 정책. 시각 특징은 ① 후보 탐지 ② 사용자 안내에 사용하며 **독립적인 자동 실행 증거가 아님**.
- **결정 필요 신호 우선:** 결제·동의·계정·개인정보·입력칸. 위험 가능성만 있으면 안전성 판단에서 중단, 다만 화면의 의미를 근거 없이 단정하지 않음.
- **시각 광고(미검증 최초):** 자동 닫기 금지. 사용자가 직접 의미를 확인·실행한 뒤 반복 규칙을 만들 수 있음.
- **실패:** 이미지에만 중요 정보, 광고 표시 위조, 언어 변형. '판단 불가'를 정상 결과로 허용.
- **검증:** 4분류 혼동행렬 + **광고(트리), 시각 광고(확인됨), 시각 광고(불확실)** 각각의 자동 처리 가능 비율과 위험 화면 오분류율.

### F8. 안전 결정 엔진

- **목적:** F7 표시 분류와 관계없이 화면 조작의 허용 범위를 결정.
- **구현:** 3장 단일 결정표(`deny` → `needs_confirmation` → `allow`), 변경된 상태/보호 플래그 우선.
- **규칙:** 중요 선택을 대신 승인하지 않음. 재사용 규칙은 해당 화면 **내용과 대상 버튼까지 일치**할 때만. 시스템 오류·내용 변경 시 자동화 취소.
- **실패:** 버튼 의미를 앱이 숨기거나 다른 행동으로 구현. 위험성이 애매하면 확인으로 전환.
- **검증:** 자동 처리 범위와 위험 클릭율을 함께 보고; 아무것도 안 눌러서 안전성만 달성한 설계는 합격시키지 않음.

### F9. 실행·결과 확인

- **목적:** 실제 클릭 전 마지막 검사와 사후 결과 확인.
- **구현:** 실행 1회에는 노드 `ACTION_DISMISS` **또는** `ACTION_CLICK` 한 번만 포함. `false`/예외/타임아웃이면 **자동 좌표 재시도 금지**. 좌표 기반 E4는 별도의 사용자 승인 행동만.
- **재검사:** 앱/창 ID, 노드 범위·텍스트, 팝업 구조·본문 지문, 민감 여부, 보호 상태, 사용자 조작, 대상 동작 등급. 클릭 이후 창 소멸·남음·외부 이동·위험 화면 진입을 구분.
- **결과:** 팝업 사라짐 = 기계적 성공; **안전한 의도로 닫힘**은 별도 사용자 확인·시험 정답에 의해서만 평가. 타임아웃 수치는 앱 실측 후 결정, ANR 5초는 근거로 쓰지 않음.
- **복구:** 자동 뒤로 가기 금지. 오작동이면 자동화 중단·설정 해제 가능. 동의/결제 취소를 약속하지 않음.
- **검증:** 기계적 클릭 성공률, 잘못된 행동 수, 오작동 후 추가 실행, TalkBack 제스처 충돌.

### F10. TalkBack 안내와 사용자 통제

- **목적:** 팝업이 등장했고 무슨 일이 발생했는지 사용자에게 알려줌.
- **구현:** 접근성 오버레이에 명확한 안내 텍스트와 조작 버튼, 접근성 pane 제목·live region을 적용. 필요 시 자체 TTS. TalkBack과 중복 낭독 여부 확인.
- **상태 구분:** `UI_UPDATED`(텍스트 갱신), `FOCUS_OBSERVED`(접근성 포커스 관측), `TTS_COMPLETED`(자체 TTS 재생 종료), `USER_ACKNOWLEDGED`(사용자가 확인). **앞의 세 가지는 사용자가 문장을 들었거나 이해했다는 증거가 아님.**
- **공지:** 첫 공지 또는 바뀐 내용은 **우선 읽고 묻기**. 같은 본문을 반복해 자동 닫는 기능은 해당 내용과 버튼이 완전히 일치하는 경우에만 별도 허락하에 사용. 자동 닫기 후에도 [다시 듣기]·[공지 기록] 접근 가능. 화면 내 중요한 내용이 바뀌면 기존 허락 적용하지 않음.
- **포커스:** 기본적으로 강제 이동 없음. 사용자가 요청하거나 사라진 포커스를 안정적으로 재확인한 때만 최소 복구.
- **검증:** 안내 생성률뿐 아니라 **당사자가 실제 들었다고 보고한 비율**, 정보 재현, 중복 음성, 포커스 손실, 처리 시간.

### F11. 이벤트 관리·연속 팝업

- **목적:** 사용자 조작과 충돌하지 않으며 같은 팝업 중복 처리 방지.
- **구현:** 단일 실행 큐, 화면 세대 ID, 행동 장부, 상태 기계(`DETECTED→EVIDENCE→WAIT_USER/ACTION_PENDING→EXECUTED→VERIFIED/FAILED`).
- **규칙:** 시스템/TalkBack 포커스 이동인지 사용자 스와이프인지 시간만으로 확정하지 않음. 불명확하면 사용자 조작을 우선 가정해 실행 보류. 자체 안내창 이벤트는 새 외부 팝업으로 취급하지 않음.
- **연쇄:** 팝업 종료 후 처음부터 보호 검사·분류 수행. 앱 세션 내 연쇄 실행 상한과 사용자 취소/일시정지 버튼 제공. 중복 이벤트 무시와 **실제 새로운 팝업 무시**를 구별.
- **검증:** 중복 클릭, 사용자 터치와 충돌, 누락한 다음 팝업, 출처 오분류, 차단기 해제 정확도.

### F12. 사용자 허락과 기억

- **구현:** Room/SQLite에 앱 ID·팝업 구조/중요 본문 지문·버튼 서술자·사용자 선택·버전·만료·실패 횟수를 저장. 원본 화면/공지 전체 텍스트는 기본 저장하지 않음.
- **규칙:** **동일한 공지 본문**만 재허락을 재사용. 숫자·날짜만 바뀌어도 새로운 공지로 보고 재확인. 자동 닫기가 가능한 반복 유형을 추후 연구하더라도 변경 범위와 사용자 선호를 별도로 검증해야 함. '묻지 마'는 **자동 닫기**와 다르다.
- **주의:** 해시도 특정 화면을 반복 식별할 수 있으므로 개인정보 보호 대상에서 완전히 제외되지 않는다. 추적·백업·내보내기 방식을 제한.
- **검증:** 기억 재사용 정확도, 중요한 공지 누락, 기억으로 인한 오작동, 사용자 기록 삭제 기능.

### F13. 음성 명령

- **구현:** 누르고 말하기. Android 12/API 31+에서 `SpeechRecognizer.isOnDeviceRecognitionAvailable()` 검사 후 `createOnDeviceSpeechRecognizer` 사용 가능. 미지원이면 접근성 버튼 선택. 사용자 의사 없이 항상 듣기 금지.
- **규칙:** `닫아`, `읽어줘`, `그대로 둬`, `건너뛰어`, `돌아가`, `버튼으로 이동`, `그림 설명`, `무슨 영상이야`. 위험 동작은 음성으로도 대행하지 않음.
- **검증:** TalkBack 낭독 도중 마이크 혼입, 오인식, 취소·반복, 접근성 오버레이 버튼의 실제 탐색 가능성.

## 5. 클라우드 AI와 개인정보

### 5-1. 권장 방식

| 판 | 네트워크 권한 | 설명 |
|---|---|---|
| 기본판 | 직접 `INTERNET` 권한 없이 설계하되 최종 병합 매니페스트 확인 | 접근성 API + 로컬 OCR + 실제 동작 검증된 로컬 모델. 고급 이미지 설명 모델이 없으면 부분 기능으로 명시 |
| 확장판(별도 선택) | 필요 | 특정 팝업에 대해 사용자가 요청한 경우만 이미지·추출 정보를 전송. 보호 앱과 민감 화면은 제외 |

- '인터넷 권한이 없음'은 앱 프로세스의 직접 네트워크 사용을 제한하는 강한 조치지만 화면 정보가 다른 앱에 공유되거나 로컬에 남는 위험까지 없애지는 않는다.
- **클라우드 전송 기본 꺼짐.** 자동 감지됐다는 사실은 업로드 동의가 아니다.
- 가능하면 텍스트만 전송하는 선택지 제공. 그림을 보내야 할 경우 **이미지 사전보기→민감정보 가림 상태 확인→사용자 명시적 전송** 순서.
- 전송 금지 앱: 금융/결제/로그인/권한, 메신저, 메일, 연락처, 건강/사진 등 민감한 앱(사용자 조정 가능, 절대 금지 화면은 해제 불가).
- OCR의 모든 글자 가림+얼굴 흐림은 보조 수단일 뿐 **OCR 누락·얼굴/신분증/QR·배경 개인정보를 완벽히 제거한다고 보장하지 않는다**. 보호 여부가 불확실하면 전송 금지.
- 원본 화면·개인정보를 예외 로그/분석 서버에 남기지 않는다. 사용자에게 처리 주체와 서버 보관 정책을 고지.

## 6. 사례별 실행 예시 (가상 시나리오; 구현 성공 결과 아님)

| 상황 | 인식 | 허용 행동 | 실패 시 |
|---|---|---|---|
| 일반 쇼핑 광고, 명시적 '닫기' 노드, 사용자가 자동 닫기 켬 | 광고 표시+E2+민감 징후 없음 | 검증된 해당 화면에서만 자동 닫기 | 화면 바뀌면 정지 |
| 처음 보는 이미지 광고, OCR 'AD'+X+설치 | **시각 광고 후보** | **자동 금지**, 이미지 안내+버튼 후보 제시 | 그림/버튼 불명확하면 조작 안 함 |
| 이전에 직접 확인한 반복 이미지 광고 + E3 바인딩 | 패키지·화면 본문·버튼 특징 일치 | 위험 신호 없을 때만 자동 가능 | 항목 바뀌면 재허락 |
| 내용 없는 X, 접근성 노드 자체 없음 | E4 후보 | 자동 안 함; 기기별 제스처 시험 통과 후 사용자 요청 때만 | '직접 누르기'가 불가능하면 제한 명시 |
| 처음 보는 점검 공지 | 공지로 보임 | 내용 안내→사용자에게 묻기 | OCR 실패면 자동 닫지 않음 |
| 동일 공지 반복 + 같은 본문 허락 | 본문 완전 일치, 버튼 동일 | 사용자가 지정한 반복 처리 허용 | 내용 변화 시 다시 묻기 |
| 점검 일시 또는 금액 변경 | 본문 지문 변경 | **자동 취소**, 변경 내용 읽고 묻기 | 핵심 항목 판독 불가면 그대로 둠 |
| 무료 체험 결제 유도 + X | 결정 필요 | 자동 안 함; 본문 안내 및 원래 앱에서 직접 선택 | 승인 버튼 대행 안 함 |
| 영상 광고 표시가 없는 영상 팝업 | '영상 창' | [무슨 영상이야?] / [닫기 후보 찾기] | 광고로 추정해 자동 닫지 않음 |
| 결제/금융 앱에서 팝업 발생 | F0-A 보호 차단 | 외부 조작 안 함 | 직접 사용하도록 안내 |
| 공지 뒤 광고 뒤 시스템 권한 창 | 세 번 모두 새로운 보호·분류 수행 | 공지 확인, 검증 광고만 처리, 권한창 중단 | 연쇄 오류 시 차단기 |

## 7. 구현에 필요한 Android 구체 항목

### 7-1. 기본 기술 스택(제안)

- Kotlin, Android Studio/Gradle, `AccessibilityService`, `AccessibilityServiceInfo`/`AccessibilityNodeInfo`, Kotlin Coroutines, Room, ML Kit Text Recognition v2(한국어), OpenCV 또는 이미지 아이콘 탐지 모델, 필요 시 자체 LiteRT/TFLite 기반 비전 모델.
- UI: TalkBack에서 읽히는 의미 있는 버튼 라벨이 있는 접근성 오버레이. 오버레이에 접근하기 어려운 기기에는 사용자가 직접 실행하는 Activity 및 TTS 경로.
- 모델 처리기는 `ImageExplainer` 인터페이스 뒤에 두고 `LocalCaptioner`, `ForegroundMlKitExplainer`, `LabelOnlyFallback`, `OptInCloudExplainer`로 교체 가능하도록 설계.
- 최소 지원 환경 선택은 팀이 결정하되, 이미지 기반 기능에는 Android 11/API 30 이상을 권장. Android 10 이하는 트리만 지원하는 제한 모드라고 표시.

### 7-2. 접근성 서비스 선언 시 확인 항목

`android.permission.BIND_ACCESSIBILITY_SERVICE`를 요구하는 접근성 서비스 선언, `android.accessibilityservice` 메타데이터, `canRetrieveWindowContent`, `flagRetrieveInteractiveWindows`, 필요한 이벤트·피드백 설정, 스크린샷 기능용 `canTakeScreenshot`, 실제 제스처가 필요할 때 `canPerformGestures`를 공식 API 기준으로 설정. **권한·플래그 존재만으로 모든 다른 앱의 정보를 읽을 수 있다고 주장하지 않는다.**

### 7-3. 주요 기능 지원 범위

| 기술 | 플랫폼/제약 | 조치 |
|---|---|---|
| `getWindows()` | 내용 조회 능력과 `FLAG_RETRIEVE_INTERACTIVE_WINDOWS` 필요 | 없으면 단일 창 노드 경로만 |
| `takeScreenshot()` | API 30+ | 캡처 권한·보안 화면·속도 제약 검사 |
| `takeScreenshotOfWindow()` | API 34+ | 창 ID·오버레이·보호 화면 실험 |
| `dispatchGesture()` | API 24+, `canPerformGestures` | TalkBack 동시 실행에서 실제 클릭인지 검증 필수 |
| ML Kit Text Recognition v2 | 한국어 OCR 가능 | 모델 배포/초기 다운로드·실행 속도 점검 |
| ML Kit GenAI | 지원 기기·모델 상태와 **최상위 포그라운드 실행 제한** | 접근성 서비스 주력 경로로 사용하지 않음 |
| 자체 LiteRT/TFLite 비전 모델 | 모델 구성·추론 가능 여부에 따라 다름 | **기기별 백그라운드 실제 추론 시험 후** 적용 |
| AudioPlaybackCapture | API 29+, 사용자 동의·다른 앱의 허용 필요 | 오디오 캡처 불가능하면 영상 시각 정보만 안내 |

## 8. 실제 검증 계획 및 합격 조건

### 8-1. 데이터·시험 방법

1. 팝업 유형별 정답 세트: 광고/공지/결정 필요/판단 불가, 이미지·영상·WebView·캔버스·노드 없음·라벨 없음, 민감 화면, 일반 화면 전환/키보드 등 오탐 대상 포함.
2. 평가자 두 명이 독립적으로 팝업 여부·핵심 내용·버튼의 정답 행동을 표시하고, 불일치는 조정/판정.
3. 규칙 개발용과 최종 평가용을 **앱 단위**로 분리. 사용자 확인 후 자동화한 화면과 완전 미지 화면을 다른 집단으로 보고.
4. TalkBack 단독(A), 기존 광고 스킵 앱을 함께 사용한 경우(B), 닫아줄게(C)를 **같은 실제 과제**에서 비교. 자동화의 작동 조건과 경쟁 앱 지원 범위를 별도로 기록.
5. 시각장애인 당사자 테스트에서는 사전 동의, 중단권, 민감 데이터 없는 시험 계정을 사용. 화면을 가린 비장애인 테스트는 당사자 평가를 대체하지 않음.

### 8-2. 지표

| 영역 | 핵심 지표 | 합격 방향 |
|---|---|---|
| 팝업 감지 | 정밀도·재현율·유형별 미탐 | 핵심 유형에서 재현 가능한 개선 |
| 이미지/영상 설명 | 핵심 내용 일치, 환각, 중요한 정보 누락 | 단순 OCR·라벨링과 비교, 시각장애인 내용 이해 시험 |
| 라벨 없는 버튼 | 감지·정답 의미 인식·실제 닫기 성공 | TalkBack 대비 접근 성공률 및 조작 수 개선 |
| 분류 | 4분류 혼동행렬, 결정 필요 오분류 | 위험 화면을 광고 자동 대상으로 잘못 옮긴 사건 별도 기록 |
| 자동화 | 자동 닫기 비율, 사용자 확인 비율, 실패·오클릭 | **안전성뿐 아니라 적용 범위**도 평가 |
| 민감 보호 | 보호 대상 캡처/로그/클라우드 노출, 누락 | 관측된 위반 0을 목표. 시험 0건 ≠ 미래 완전 무오류 |
| 안내 | 실제 들은 정보 이해도, 재청취, TalkBack 중복·포커스 손실 | 포커스 이벤트 수만으로 평가하지 않음 |
| 효용 | 작업 완료율·시간·스와이프 횟수·SUS·인터뷰 | A/B 대비 C의 개선 정도와 부작용 모두 보고 |

### 8-3. 우선 검증해야 할 **합격 관문**

- **G1 화면 정보 확보:** 접근성 노드가 부실한 팝업에서 캡처·OCR 또는 화면 설명 경로가 실제로 가능한가?
- **G2 백그라운드 이미지 의미 분석:** 실제 다른 앱을 이용 중일 때 로컬 모델이 내용을 설명할 수 있는가? ML Kit GenAI는 포그라운드 제한이 있으므로 주력으로 가정하지 않음.
- **G3 안전한 버튼 실행:** 라벨 없는 클릭 노드와 노드 없는 X에서 TalkBack 동시 실행 결과가 무엇인가? 실제 성공/오동작 분리.
- **G4 음성 안내:** TalkBack 안내가 실제 사용자에게 전달되고, 다시 들을 수 있으며, 포커스를 뺏지 않는가?
- **G5 분류/사용성:** 처음 보는 이미지 팝업을 자동으로 과감하게 닫지 않아도 사용자가 기존보다 빠르고 안전하게 본문에 접근할 수 있는가?

**이 관문이 실패하면 문서만 다시 쓰지 말고 해당 기술·사용 흐름 자체를 재설계한다.**

## 9. Google Play와 외부 배포

- 개발/수업 시연을 Google Play 승인 가능성과 혼동하지 않는다.
- Google Play 정책은 다른 앱의 광고 표시를 차단·방해하는 앱을 위반 사례로 제시한다. 광고를 보여 준 다음 닫기 버튼을 누른다는 방식이나 사용자 동의가 정책 준수를 **자동 보장하지 않는다**.
- 접근성 서비스의 장애인 지원 목적과 `isAccessibilityTool` 선언은 중요하지만, **광고 방해 규정이 자동 면제되는 것은 아님**. 정식 출시 전 정책 검토·문의가 필요하다.
- 외부 설치 기기에서의 접근성 권한/제한된 설정 안내, 개인정보처리방침, 화면 분석에 대한 명확한 동의 및 중지 방법을 별도로 준비한다.

## 12. 최종 결론

v5는 **'범용 팝업을 AI가 다 이해하고 자동으로 닫는다'**는 과장 대신, 실제 접근성 API로 확인 가능한 정보와 로컬 시각 분석을 이용해 **안내 가능한 범위를 넓히고, 반복 검증된 안전한 닫기만 자동화**하는 시스템으로 정의한다.

개발 목표는 유지한다. 다만 **접근성 정보가 전혀 없는 이미지 광고의 첫 자동 닫기, 보호된 화면의 무조건 캡처, ML Kit GenAI의 백그라운드 추론, 모든 영상 내용의 완전한 이해**는 현재 기술로 보장되지 않음을 명확하게 표시한다.

**문서의 상태: v5 설계 초안 — 구현 및 당사자 검증 전. 최종 기술 명세 확정은 G1~G5 실험 이후.**
