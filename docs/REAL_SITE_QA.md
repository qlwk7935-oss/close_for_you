# 실제 사이트·앱 시행 기록과 집계 (D)

담당: 동준/D. 최종 시연(AGENTS.md 6-0·9장)에서 재호·우진이 실제 사이트·앱으로 시험한 결과를 같은 양식으로 모으고, D가 집계해 증명 자료로 씁니다. 재현 앱(P·N 시나리오)은 기존 [`QA_METRICS.md`](QA_METRICS.md)를 그대로 씁니다.

**상태: 양식과 집계 도구만 준비했습니다. 실제 시행 기록은 0건입니다.** 집계 도구는 합성 데이터로만 시험했습니다(`tools/test_real_site_metrics.py`).

## 1. 지켜야 할 것

- **화면 원문을 적지 않습니다.** 팝업 문구, 상품 이름, 계정, 스크린샷 경로를 기록에 쓰지 않습니다. 사이트 ID, 코드, Y/N, 숫자만 적습니다. 집계 도구는 `notes`·`clicked_target`에 한글이 있으면 입력 문제로 멈춥니다.
- 로그인이 필요한 곳은 시험자 본인 계정으로 하고, 계정 정보는 어디에도 적지 않습니다.
- 결제·구매·동의·권한·구독·삭제 버튼은 시험 중에도 누르지 않습니다(6-0 유지 항목). 앱이 눌렀다면 `forbidden_click=Y`로 적고 바로 알립니다.

## 2. 팝업 다시 띄우는 방법 (사이트별 재현)

이벤트 팝업은 "오늘 하루 보지 않기"나 방문 기록 때문에 두 번째부터 안 뜰 수 있습니다. 시행마다 아래처럼 초기화합니다. 사이트별로 실제로 다시 뜨는지는 리허설에서 확인해 정답지 `status`에 반영합니다.

| 방식 | 초기화 | 비고 |
|---|---|---|
| 크롬 웹 | 크롬 → 설정 → 사이트 설정 → 모든 사이트 → 해당 사이트 → 데이터 삭제 후 다시 접속 | 로그인도 풀릴 수 있음 |
| 크롬 웹(간단) | 시크릿 탭으로 접속 | 쿠키가 없는 상태라 첫 방문 팝업이 다시 뜰 수 있음. 시크릿 탭에서 우리 앱 동작이 같은지는 확인 필요 |
| 앱 | 설정 → 앱 → 해당 앱 → 저장공간 → 데이터 삭제(또는 캐시 삭제 먼저 시도) 후 다시 실행 | 로그아웃됨. 첫 실행 안내·권한 요청이 같이 뜰 수 있음 |
| 크롬 권한 요청(L20) | 크롬 → 설정 → 사이트 설정 → 알림 → 해당 사이트 권한 초기화 | 허용을 누르지 않음 |
| 닫아줄게 | 기억 전체 삭제, 접근성 서비스 껐다 켬(세션 기록 초기화) | [진행표](DEMO_SCRIPT.md) 2절과 같음 |

시간대·로그인 여부에 따라 팝업이 바뀌므로 리허설과 발표는 가능하면 같은 조건(로그인 여부, 같은 기기)으로 합니다.

## 3. 시행 기록 양식 (한 번 시험 = 한 줄)

| 열 | 값 | 설명 |
|---|---|---|
| `trial_id` | 예: `R1104-07` | 겹치지 않게 |
| `site_id` | `L01`~`L20` | 정답지의 ID |
| `date` | `2026-11-01` | |
| `tester` | `A`·`C` | 실측 담당 |
| `device`, `android`, `app_build` | 기기 모델, 안드로이드 버전, 닫아줄게 빌드(커밋 앞 7자리) | |
| `talkback` | Y/N | |
| `mode` | `ASK`·`PRESET`·`ALWAYS`·`AUTO_SKIP` | 묻기, 프리셋 자동 닫기, 앞으로 항상 닫기, 자동 건너뛰기 |
| `preset` | `OFF`·`CLOSE_ALL`·`CLOSE_ADS_AND_COUPONS`·`CLOSE_ADS_ONLY` | |
| `popup_appeared` | Y/N | 팝업이 실제로 떴는지(사람 기준). N이면 집계에서 뺌 |
| `detected` | Y/N | 닫아줄게가 팝업을 알아챘는지 |
| `observed_kind` | `ADVERTISEMENT`·`COUPON`·`NOTICE`·`USER_DECISION`·`SUSPICIOUS`·`UNKNOWN`·`BLOCKED` | 닫아줄게가 말한 분류 |
| `outcome` | `CLOSED_BY_APP`·`USER_CONFIRMED`·`ASKED_ONLY`·`WARNED`·`MISSED`·`NOT_RUN` | 앱이 알아서 닫음, 사용자가 고른 뒤 앱이 누름, 안내만, 경고만, 못 알아챔, 시험 못 함 |
| `clicked_target` | `CLOSE`·`SKIP`·`NONE` 또는 금지 코드(`BUY`·`HIDE_TODAY`·`INSTALL_APP`…) | 앱이 누른 버튼의 역할 코드 |
| `closed_verified` | Y/N | 누른 뒤 팝업이 실제로 사라졌는지 |
| `forbidden_click` | Y/N | 앱이 정답지 금지 대상을 눌렀는지 |
| `misclick` | Y/N | 팝업이 아닌 곳·엉뚱한 버튼을 눌렀는지 |
| `info_correct` | Y/N | 안내 문장이 화면과 맞았는지(예: 안 닫혔는데 "닫았어요"면 N) |
| `seconds_to_close` | 숫자 | 팝업이 뜬 뒤 닫힐 때까지 초(대략, 영상 타임스탬프 기준) |
| `rehearsal` | Y/N | 리허설 시행이면 Y |
| `notes` | 코드만 | 예: `F9_WIDGET;LOGGED_OUT`. 원문 금지 |

## 4. 집계와 지표 표

```bash
python3 tools/real_site_metrics.py trials.csv                      # 전체
python3 tools/real_site_metrics.py trials.csv --rehearsal-only     # 리허설만 (11/4)
```

| 지표 | 정의 | 목표 |
|---|---|---|
| 감지율 | 팝업이 뜬 시행 중 닫아줄게가 알아챈 비율 | 높을수록 |
| 기대 분류 일치 | `observed_kind`가 정답지 `expected_kind`와 같은 비율 | 높을수록 |
| 닫힘 성공률 | 정답지 CLOSE_OK 사이트에서 앱이 누르고 실제로 닫힌 비율 | 높을수록 |
| 시행 통과율 | 아래 통과 기준을 만족한 비율 | 높을수록 |
| **금지 버튼 클릭** | 건수 | **0건** |
| **오클릭** | 건수 | **0건** |
| 안내 정확도 | `info_correct=Y` 비율 | 높을수록 |
| 닫힘 시간 | 통과 시행의 중앙값(초) | 짧을수록 |

통과 기준(시행 하나):
- 금지 버튼·오클릭·틀린 안내가 있으면 실패.
- CLOSE_OK: 앱이 누르고 실제로 닫혀야 통과. 누르지 않았거나 닫힘을 확인 못 하면 실패.
- ASK: 묻기만 했거나 사용자가 고른 뒤 닫혔으면 통과. 앱이 알아서 닫으면 실패(목표 밖 자동 처리).
- NO_PRESS: 아무것도 누르지 않아야 통과.

사이트별 표에는 시험·통과·실수 수와 실패 사유 코드가 나오고, **시험 3회 이상·실수 0회**인 사이트를 "시연 후보 Y"로 표시합니다(`--min-trials`로 바꿀 수 있음). 금지 버튼이나 오클릭이 1건이라도 있으면 종료 코드 1입니다.
