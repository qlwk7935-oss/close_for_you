## 슬라이드 1. 프로젝트 소개 — 필요성과 제안 방법 (팀 공통)

**넣을 내용**
- **문제:** 시각장애인이 TalkBack으로 앱을 쓰는데 광고·공지 팝업이 뜨면, 닫기 버튼을 찾기 어렵다.
- 닫기 버튼이 "이름 없는 X"인 경우가 많아 TalkBack이 "버튼"이라고만 읽는다.
- 닫기 옆에 **결제·동의·구독 버튼**이 있으면, 잘못 누르는 순간 돈이 나가거나 동의가 된다.
- **제안:** 팝업을 감지해서 → 분류하고 → 안전한지 판단하고 → 사용자가 정한 방식(프리셋)대로 처리하고 → **TalkBack과 음성으로 무슨 일이 있었는지 알려 준다.**
- 단순 광고 차단이 아니라 **사용자가 선택하는 것을 돕는 앱**이다. 화면 정보는 밖으로 보내지 않는다(인터넷 권한 없음).

**그림·표 제안**
- 흐름 그림 한 장: `팝업 감지(A) → 분류(B) → 안전 판단(B·A) → 프리셋 처리 → 음성 안내(C)`. C 구간만 색을 다르게.
- 왼쪽에 "이름 없는 X + 결제 버튼" 팝업 그림 한 장.

**발표자 한 줄:** "화면을 못 보는 사람에게 팝업은 '닫기 버튼 찾기'가 아니라 '잘못 누르면 결제'가 되는 문제입니다."

## 슬라이드 2. 차별성 — 기존 방법과 무엇이 다른가 (C 관점)

**넣을 내용**
- 기존 **광고 차단**은 웹 중심이고, 화면을 보는 사람 기준이다. "무엇을 막았는지"를 소리로 알려 주지 않는다.
- **TalkBack 기본 동작:** 다른 앱 위에 새 창이 떠도 **창 제목을 스스로 읽지 않는다.** (LG 실기기 실험으로 발견 → 그래서 앱이 직접 소리로 알린다.)
- **일반 접근성 앱**은 읽어 주기까지만 하고, "무엇을 누를지 / 누르면 안 되는지"는 판단하지 않는다.
- 우리는 **누를 버튼의 이름을 먼저 말해 주고**, 사용자가 확정한다.
- 우리는 **TalkBack 포커스를 뺏지 않는다.** 결제·동의·구독·삭제·권한은 **대신 누르지 않는다.** 처리 범위는 **프리셋으로 사용자가 정한다.**

**그림·표 제안 (비교표)**

| | 웹 광고 차단 | TalkBack 기본 | 일반 접근성 앱 | **닫아줄게** |
|---|---|---|---|---|
| 앱 안 팝업 | 대상 아님 | 읽기만 | 읽기만 | 감지(A)·분류(B) |
| 새 창을 소리로 알림 | 없음 | 창 제목을 안 읽음(LG) | 앱마다 다름 | **0.7초 뒤 앱이 직접 안내** |
| 누를 버튼 이름 확인 | 없음 | 없음 | 없음 | **이름을 말하고 사용자가 확정** |
| 결제·동의 대신 누름 | — | — | 앱마다 다름 | **절대 안 함 (버튼 자체를 안 보임)** |
| 처리 범위 결정 | 사용자 몫 아님 | — | — | **프리셋 3개** |
| 화면 정보 | 서버 사용 많음 | — | 앱마다 다름 | **기기 안에서만, 인터넷 권한 없음** |

> 표의 "웹 광고 차단·일반 접근성 앱" 칸은 일반적인 성격을 쓴 것입니다. **특정 제품 이름으로 단정하려면 팀이 조사해서 확인**하세요(○○).

**발표자 한 줄:** "TalkBack은 새로 뜬 팝업 창을 스스로 읽지 않는다는 것을 실기기에서 확인했고, 그 빈틈을 우리 앱이 메웁니다."

## 슬라이드 7. 예상 질문과 답

1. **"지금 실제로 광고를 닫나요?"**
   아직 아닙니다. 실제 자동 클릭(F9)은 만들지 않았고, A의 실행 관문은 지금 "누르지 않음" 상태입니다. C가 한 것은 선택 창, 음성 안내, 설정입니다. 지금까지의 실기기 확인은 가짜 팝업 기준입니다.

2. **"왜 바로 닫지 않고 사용자에게 묻나요?"**
   광고처럼 보인다는 이유만으로 처음 보는 팝업을 누르면 결제·동의 버튼을 잘못 누를 수 있어서입니다. 그래서 사용자가 정한 프리셋과 안전 조건이 모두 맞을 때만 자동으로 닫도록 설계하고 있고, 그 부분은 아직 연결 전입니다.

3. **"음성 명령이 TalkBack 소리나 영상 소리를 명령으로 잘못 들으면요?"**
   [말하기]를 누를 때만 한 번 듣고, 누르면 우리 안내가 먼저 멈춥니다. 결제·동의·구독·삭제·권한 같은 말은 명령으로 받지 않습니다. 단, 음성 인식 자체는 LG가 지원하지 않아 **실기기에서는 아직 검증하지 못했습니다** (S26 예정).

4. **"TalkBack이 이미 있는데 왜 앱이 따로 말하나요?"**
   LG 실험에서 TalkBack은 새로 뜬 오버레이 창의 제목을 스스로 읽지 않았습니다. 그래서 0.7초 뒤 짧게 직접 안내하고, TalkBack을 끊거나 포커스를 뺏지 않는 것도 확인했습니다. 설정에서 끌 수 있습니다. 삼성 TalkBack은 아직 확인 전입니다.

5. **"개인정보는요? 화면 내용이 밖으로 나가나요?"**
   인터넷 권한이 없고 음성 인식도 기기 안에서만 씁니다. 팝업 글자와 들은 말은 로그·파일에 남기지 않습니다. 이 부분은 코드 규칙과 시험으로 확인했습니다. 실제 사용 중 화면 내용 보호는 A의 민감 화면 보호와 함께 검증합니다.

(예비) **"프리셋을 고르면 뭐가 달라지나요?"** — 지금은 선택이 저장될 뿐 동작은 안 바뀝니다. 자동 닫기가 연결될 때 쓰이고, 중요 결정은 어느 프리셋이어도 항상 사용자에게 묻습니다.
