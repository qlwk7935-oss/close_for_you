## 2. 빈 멈춤 원인 조사 (debug 도구, 글자 원문 기록 없음)

C 시험 서비스에 debug 전용 `OverlayNodeDump`를 붙여 창 목록과 노드의 성질(초점 가능·클릭·중요도·글자/설명 **길이만**)을 logcat `C34Nodes`에 찍었다.

```
adb -d shell am start -n kr.closeforyou/.ui.voice.debug.ChoicePreviewActivity --el ui_debug_c34_focus_ms 170000
(→ 평소처럼 scenario 0 → P01. 9초 뒤 창 목록·노드 한 번 기록)
adb -d shell am start -n kr.closeforyou/.ui.voice.debug.ChoicePreviewActivity --ez ui_debug_c34_dump true   # 노드만 (미리보기 화면이 앞으로 옴)
```

> 10/24 PR #34 리뷰 반영: `focus_ms`는 **기본 읽기 전용**(초점 이벤트·노드 기록만, 선택 창이 뜬 4초 뒤 노드 한 번). TalkBack 초점을 C 첫 노드로 옮기려면 `--ez ui_debug_c34_focus_move true`를 함께 줘야 하고, 그때도 같은 서비스 연결·같은 C 창 세대·창 안 노드가 그대로일 때만 옮긴다(이미 C 창 안에 초점이 있으면 안 옮김). 감시는 시간이 다 되면 이벤트가 없어도 끝나고, 새 요청·창 닫힘·interrupt/unbind/destroy 때 예약이 모두 취소되며 서비스 설정이 원래대로 돌아간다(`FocusWatchSchedule`, JVM 시험 9개). 실기기 재확인 미실시.

### 2-1. C 선택 창 안 (측정)

| 노드 | 초점 가능 | 글자 | 판단 |
|---|---|---|---|
| ComposeView(창 뿌리) | 아니오 | 없음 | 창과 크기가 같은 뿌리 — TalkBack이 멈추지 않는 노드 |
| View(Compose 내부) | 아니오, 중요도 false | 없음 | 해당 없음 |
| ScrollView(paneTitle 5자, 스크롤 안 됨) | 아니오 | 없음 | 초점·클릭 없음 |
| 요약 TextView | 화면 읽기 초점 | 14자 | 정상 |
| 버튼 5개(View, 클릭) | 예 | 자식 글자 13·8·6·5·6자 | 정상. 자식 "Button"은 Compose가 역할 이름용으로 넣는 빈 노드(초점·클릭 없음, 부모가 초점 가능) |
| 상태 줄·안내 줄 | **노드 없음** | — | `messageRes`/`hintRes`가 null이면 그리지 않음 |
| [다시 듣기]·[그만 말하기]를 감싼 Row | **노드 없음** | — | semantics 없는 Row는 노드가 생기지 않음 |

traversalBefore 사슬도 요약 → 버튼1 → 2 → 3 → 다시 듣기 → 그만 말하기 순서 그대로(마지막은 없음).

**결론: C 창에는 글자 없이 초점을 받을 노드가 없다.** 의심했던 빈 상태 줄·Row/Column·verticalScroll은 원인이 아니다.

### 2-2. 화면의 다른 창 (TalkBack 창 순서 = 층 높은 순)

| 층 | 창 | 비고 |
|---|---|---|
| 3 | C 선택 창 (TYPE_ACCESSIBILITY_OVERLAY) | 위 표 |
| 2 | **시스템 창: 접근성 플로팅 메뉴 버튼**(x 911~1122, y 1993~2204 — 오른쪽 끝에 반쯤 숨어 C 창 '내용 다시 읽기'·'그대로 두기' 옆에 겹침) | 안의 `RecyclerView`가 **초점 가능인데 글자·설명 없음**. 그 안 버튼은 설명 8자("텍스트 읽어주기" 길이와 같음) |
| 1 | 상태 표시줄 | |
| 0 | P01 대화상자 | 제목·본문·자세히 보기·닫기, 빈 노드 없음 |

**재확인 결론(사용자, 같은 날):** 빈 멈춤은 C 창 안에서 생기지 않았다. 마지막 항목에서 오른쪽으로 쓸면 TalkBack이 진동으로 "끝"을 알리고, 한 번 더 쓸면 첫 항목(요약)으로 돌아간다. 처음 본 "한 번 쓸어도 아무것도 안 읽음 → 요약으로 감"은 이 동작으로 설명된다. 아래 플로팅 메뉴 가설은 측정 기록으로만 남긴다.

**처음 세운 가설(실기기 TalkBack 동작은 미확인):** "그만 말하기" 다음 오른쪽 스와이프가 C 창을 벗어나 층 2의 **접근성 플로팅 메뉴** 창으로 들어가며, 이름 없는 `RecyclerView`에 멈추면 아무것도 안 읽힌다. 거기서 왼쪽으로 쓸면 TalkBack이 C 창으로 다시 들어가며 창의 첫 항목(요약)에 놓일 수 있어, "그만 말하기에서 왼쪽 → 요약"처럼 들린 것과도 맞는다. 이 창은 Android 시스템 UI라 C 코드로 고칠 수 없다.

- 시도했지만 안 된 것: `adb input swipe`(TalkBack이 adb 터치를 제스처로 받지 않음), 키보드 Alt+화살표(입력 초점 창인 P01 안에서만 움직임) → TalkBack 스와이프 재현은 사람 손으로만.
- TalkBack 로그에 `windowContentChanged: error, node is null`이 창이 뜰 때 여러 번 찍힘. 초점과의 관계는 모름.

## 3. 바꾼 것

- C 코드 동작 변경 없음(측정상 C 창에 빈 노드 없음). `ChoicePromptContent`에 상태 줄·Row가 노드를 만들지 않는 이유를 주석으로 남김.
- 회귀 시험 2개(`PromptControlsControllerTest`): LG 상태([말하기] 숨김)에서 다시 듣기·그만 말하기를 눌러도 상태 줄·안내 줄이 계속 비어 있음 / 안내 줄은 마이크 허용이 필요할 때만.
- debug 전용 `OverlayNodeDump`와 adb extra 2개(`ui_debug_c34_focus_ms`, `ui_debug_c34_dump`). release·main 영향 없음.

## 4. 재확인 순서 (사용자)

1. 선택 창을 띄우고 **요약에 손가락을 대서** 시작.
2. 오른쪽 스와이프 5번: '닫기' 버튼 눌러 주기 → 내용 다시 읽기 → 그대로 두기 → 다시 듣기 → 그만 말하기. 이 다섯 사이에 빈 멈춤이 없어야 한다.
3. 6번째 오른쪽 스와이프: 아무 말이 없거나 "텍스트 읽어주기"가 들리면 → 접근성 플로팅 메뉴(시스템). 손가락으로 오른쪽 끝 반쯤 숨은 동그라미를 만져 보면 같은 것인지 확인.
4. 그만 말하기에서 왼쪽 스와이프 1번 → "다시 듣기"가 들리는지.
5. (선택) 플로팅 메뉴를 화면 왼쪽 위 등 선택 창과 안 겹치는 곳으로 끌어 두고 2~4 반복 — 빈 멈춤이 플로팅 메뉴 때문인지 갈라 볼 수 있다. 시스템 설정은 바꾸지 않는다.
