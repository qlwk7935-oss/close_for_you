## 1. 설정 화면 (Compose)

### 1-1. 프리셋 초안

| 프리셋 | 외부 광고 | 쿠폰·이벤트 | 공지 | 판단 불가 |
|---|---|---|---|---|
| 기본 (기본값) | 자동 닫기 | 물어봄 | 읽고 물어봄 | 알림만 |
| 편리 | 자동 닫기 | 자동 닫기 | 읽고 물어봄 | 알림만 |
| 최소 방해 | 자동 닫기 | 자동 닫기 | 한 줄 요약 후 자동 닫기 | 알림만 |

⚠️ 지금과 다른 점
- **처음 보는 팝업은 광고처럼 보여도 항상 물어본다** (B 정책 F8, AGENTS.md 6-2). "자동 닫기"는 사용자가 허락한 **같은 팝업**(F12 정확 일치 규칙)에만 해당한다.
- B 제안: **앱별 자동 닫기 설정은 기본 꺼짐**, C 설정 화면에서 켜고 `DecisionContext`로 전달 (계약 추가는 합의 후 별도 PR).
- 분류는 `ADVERTISEMENT` / `NOTICE` / `USER_DECISION` / `UNKNOWN` 4개다. **쿠폰·이벤트 분류는 없다.**
- 따라서 프리셋은 "종류별 자동 닫기"가 아니라 "앱별 자동 허용 + 안내 방식" 중심으로 다시 설계해야 한다.

### 1-2. 세부 설정 초안

- 외부 광고·쿠폰: [자동 닫기 / 물어봄 / 알림만]
- 공지: [요약 후 닫기 / 읽고 물어봄 / 알림만]
- 판단 불가: [물어봄 / 알림만]
- 동의·로그인: [확인 후 대신 누르기 / 위치 안내만], 기본값 위치 안내만. 대신 누르기는 매번 내용을 읽고 오버레이 버튼 탭으로 허락.
- 고정(설정 없음): 결제·구독·삭제·권한 → 위치 안내만 / 비밀번호·금융 → 분석 중단

⚠️ 결제·구매·동의·권한·구독·삭제는 기억 규칙이나 음성 명령이 있어도 B가 금지한다. "동의 대신 누르기" 옵션은 현재 팀 결정과 맞지 않을 수 있다 → 팀 확인 필요.

### 1-3. 부가 옵션 초안

- ~~"오늘 하루 보지 않기" 우선 (기본 끔)~~ ⚠️ B가 "오늘 하루 닫기"를 **가짜 닫기 버튼으로 차단**한다. 이 옵션은 빼거나 팀 논의.
- 닫은 팝업 기록 (기본 켬)
- 안내 길이: 짧게("광고 닫았어요") / 자세히("쇼핑앱 쿠폰 광고를 닫았어요")
- 일시정지: 30분 / 1시간 / 다시 켤 때까지 ⚠️ A의 `CorePreferences.setPaused()`가 이미 있다. 시간 제한 일시정지는 A와 함께 설계.
- 앱별 예외 (금융 앱 기본 제외) ⚠️ A의 `CorePreferences`는 **허용한 앱만 분석**하는 방식이다 (기본 전부 꺼짐).
- 기억 목록 관리: D의 `PopupRuleRepository.observeRules()`로 보여 주고 `revoke()`·`deleteAll()`로 해제. `STOP_ASKING`(다시 묻지 않기)도 여기서 풀 수 있어야 한다.

### 1-4. 불변 규칙

- 분류가 애매하면 설정과 무관하게 묻는다.
- 공지는 자동으로 닫아도 최소 한 줄은 읽는다. 자동 닫기 후에도 [다시 듣기]·[공지 기록] 경로를 둔다 (설계 F10).
- 첫 실행 때 음성으로 프리셋을 묻는다.
- 모든 요소에 라벨(semantics), 탐색 순서 확인, KWCAG 점검.
- 설정 저장: C 설정은 DataStore 또는 기존 `CorePreferences` 확장 중 A와 협의. 기억 목록은 D의 Room.

## 2. TTS 안내 문장 초안

```xml
<string name="tts_ad_closed">광고 닫았어요</string>
<string name="tts_many_closed">팝업 %1$d개를 닫았어요</string>
<string name="tts_notice_ask">%1$s. 닫을까요?</string>
<string name="tts_decision_found">%1$s 창이에요. 직접 확인해 주세요</string>
<string name="tts_unknown_popup">팝업이 떴어요. 닫기 버튼은 %1$s에 있어요</string>
<string name="tts_redirected">광고 때문에 다른 페이지가 열렸어요. 돌아갈까요?</string>
```

⚠️ 지금과 다른 점
- 실제 안내 문장은 `AnnouncementRequest.text`로 **호출하는 쪽이 만들어 넘긴다.** C 문장 파일은 `res/values/ui_voice_strings.xml`, 이름은 `ui_` 접두사.
- 중요 결정은 A가 원문 대신 **고정 요약**(예: "결제 선택 필요")만 넘긴다. 가격·버튼 의미를 읽었다고 표현하지 않는다.
- "돌아갈까요?"(뒤로 가기)는 `GO_BACK`이 명령 표현일 뿐 현재 실행하지 않는다.
- "확인/OK"만 있는 팝업은 대신 닫을 수 없다 → "대신 닫을 수 없어요. 확인 버튼으로 이동할까요?" 같은 문장이 필요하다.

### 묶음 안내·기록

- 2초 안에 여러 개가 처리되면 묶어서 한 번: "팝업 3개를 닫았어요".
- "오늘 닫은 팝업 다시 듣기"용 최근 안내는 메모리에만 보관, 서비스 종료 시 삭제 (현재 `AnnouncementHistory`가 담당).

## 3. 음성 명령 초안

- 누르고 말하기만. 항상 듣기 금지. API 31+ `createOnDeviceSpeechRecognizer()`만, 미지원 기기는 버튼만.
- 명령(규칙 매칭, AI 해석 아님): 다시 읽어줘 / 닫아 / 그대로 둬 / 건너뛰어 / 돌아가 / 버튼으로 이동 / 무슨 그림이야
  - 계약 `VoiceCommand`: `CLOSE`, `SKIP`, `READ_CONTENT`, `KEEP_OPEN`, `GO_BACK`, `MOVE_TO_BUTTON`, `DESCRIBE_IMAGE`
- TalkBack 낭독 중에는 마이크를 열지 않는다 (TalkBack 소리가 마이크로 들어감).
- 예정 명령 "로그인 눌러": 요청만 음성, 실행은 화면 탭으로 확정. [팀 확정 필요]
- `RECORD_AUDIO` 권한 추가는 A 매니페스트 변경이라 함께 리뷰.
