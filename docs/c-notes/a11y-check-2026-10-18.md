# 접근성 점검 — 2026-10-18 (C, 밤 작업 세션)

- 기기: LG 벨벳 (LM-G900N), Android 12, 화면 밀도 420dpi (1dp = 2.625px)
- 대상: debug 빌드 **"닫아줄게 C 미리보기"** 화면, 같은 앱 안 **설정 화면**, 다른 앱 위 **선택 창 오버레이**
- 방법: `uiautomator dump`로 우리 앱 화면만 뽑아 버튼·선택 항목의 라벨·종류·크기를 표로 만듦. 다른 앱 화면 내용은 저장하지 않음
- **한계:** TalkBack이 실제로 **무엇을 읽는지(소리)** 는 이 방법으로 확인할 수 없다 → 아래 "사람이 확인할 것" 참고
- **주의 (발견):** `uiautomator dump`가 실행되는 동안에는 다른 접근성 서비스(우리 시험 서비스, TalkBack)가 잠깐 멈춘다. 그래서 덤프 순간에는 시험 서비스가 "꺼짐"으로 보이고, 떠 있던 오버레이도 닫힌다. 오버레이는 `adb shell dumpsys window windows`로 확인했다. (A의 서비스 시험에도 같은 영향이 있을 수 있음)

## 5. 사람이 확인할 것 (실기기 TalkBack)

1. 오버레이가 **새로 뜰 때** TalkBack이 "팝업 안내"(창 제목)를 읽는지, 우리 TTS와 겹치는지 (설정 스위치 켜고/끄고 비교)
2. 오버레이 위에서 쓸어넘기기로 버튼에 모두 도달하는지, 닫힌 뒤 TalkBack 포커스가 원래 앱의 어디로 가는지
3. 설정 화면 제목 단위 이동(TalkBack 읽기 단위 "제목"), 스위치 "켜짐/꺼짐" 읽기, [해제] 버튼이 어떤 규칙인지 읽는지
4. 큰 글꼴(설정 → 글꼴 크기 최대)에서 글자가 잘리지 않는지
5. 갤럭시 S26에서 음성 명령: 기기 안 인식 가능 여부, "닫아/건너뛰어/다시 읽어줘/그대로 둬" 인식
