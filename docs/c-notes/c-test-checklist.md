# C 검사표 — 팝업 재현 앱으로 보는 TalkBack 사용성 (재호)

> C(UI·TalkBack·음성) 관점에서 D의 팝업 재현 앱(`:popup-test-app`) 시나리오 25개(P01~P18, N01~N07)를 하나씩 확인하는 표입니다.
> 표를 채우면 그대로 **"C 검사 보고서"**가 되도록 맨 아래에 요약 칸을 두었습니다.
>
> - 작성: 2026-10-22, 갱신: 2026-10-23(공용 라벨 계약 #14 허용 14개, 재현 앱 P16~P18 #26, 첫 통합 검증표 #27과 맞춤). 브랜치 `feature/ui-voice` 코드 기준. **이 문서 자체는 아직 아무 시험도 하지 않은 빈 표입니다.**
> - 첫 통합 실측(INT1)의 기록·집계는 D의 [`docs/FIRST_INTEGRATION_CHECKLIST.md`](../FIRST_INTEGRATION_CHECKLIST.md)가 기준입니다. 이 표는 그때 C 선택 창·문장·TalkBack을 함께 보는 데 씁니다.
> - 기대값은 아래 [근거 목록](#근거-목록)의 실제 C 코드·문구에서 가져왔습니다. 코드에서 답을 찾지 못한 것은 **"실기기 확인 필요"**로 적었습니다.
> - 분류(광고·공지·중요 결정)는 **B가 정합니다.** 그래서 C 기대값은 "B가 광고로 분류하면 …"처럼 조건부로 씁니다. 팝업 감지·민감 화면 차단은 **A**입니다. C 표는 A·B의 결과를 채점하지 않고, **A·B가 준 결과를 C가 바르게 보여 주고 읽어 주는지**를 봅니다. (A·B가 틀린 것을 발견하면 비고에 적고 해당 담당에게 알립니다.)

### 1-2. 준비

1. **기기**: LG 벨벳(Android 12, TalkBack 17) 또는 에뮬레이터. 갤럭시 S26은 들어오면 따로 한 번 더.
   - LG는 기기 안 음성 인식을 지원하지 않아 [말하기]가 숨겨집니다 → 음성 명령 칸은 LG에서 **"못 봄"**. ([근거 V3](#근거-목록))
   - 에뮬레이터는 TalkBack·TTS 상태가 실기기와 다를 수 있어, TalkBack 칸은 실기기 결과만 "통과"로 적습니다.
2. **TalkBack 켜기는 사람이 폰 설정에서** 합니다(설정 → 접근성 → TalkBack). adb로 켜지 않습니다.
3. **재현 앱 설치·열기** (D 문서 `docs/POPUP_TEST_APP.md`):
   ```bash
   adb install -t popup-test-app/build/outputs/apk/debug/popup-test-app-debug.apk
   adb shell am start -n kr.closeforyou.popuptest/.PopupScenarioActivity --es scenario P01
   ```
   - 앱을 그냥 열면 시나리오 목록이 나오고, 위 명령으로 특정 시나리오를 바로 엽니다(`P01`~`P18`, `N01`~`N07`).
   - 닫아줄게 본 앱의 앱별 허용 목록에 `kr.closeforyou.popuptest`를 **직접** 추가해야 분석 대상이 됩니다(초기 목록은 비어 있음).
4. **눌린 버튼 기록 보기**:
   ```bash
   adb logcat -s PopupTest
   ```
   - 버튼이 눌리면 `시나리오:리소스ID` 한 줄만 남습니다(예: `P01:btn_close`, `P06:ad_landing_opened`). 사람이 직접 누른 것도 같은 줄로 찍히므로, **누가 눌렀는지(사람 / 선택 창 / 음성)는 비고에 적습니다.**
   - `ad_landing_opened`가 선택 창 동작 뒤에 찍히면 잘못된 클릭입니다.
5. **안내 설정 기본값** 확인(C 설정 화면 "안내·음성 설정"): 안내 길이 **짧게**, 선택 창 음성 안내 **켜짐**, 말하기 버튼 **켜짐**, 앱별 자동 닫기 **꺼짐**. ([근거 S1](#근거-목록)) 다른 값으로 시험했다면 비고에 적습니다.

### 1-3. 기록 원칙

- **화면 글자·개인정보는 적지 않습니다.** 팝업 본문, 낭독된 내용 원문, 계정, 스크린샷 경로를 표에 남기지 않습니다. (CLAUDE.md 3-3, AGENTS 6-9)
- 적는 것은 **버튼 이름(선택 창 버튼 이름과 재현 앱 리소스 ID)과 결과**뿐입니다. 선택 창 문장은 아래 표의 **문자열 이름**(`ui_choice_summary_ad` 등)으로 적습니다. 재현 앱 문구는 모두 합성이지만 습관을 위해 같은 원칙을 지킵니다.
- 결과마다 **Mock / 실기기(기기명·TalkBack 버전)**를 구분합니다. 확인하지 않은 칸은 "통과"로 채우지 않고 **"못 봄"**으로 둡니다.
- P11(로그인)에는 **실제 비밀번호를 입력하지 않습니다.**

### 1-4. 결과 칸 쓰는 법

- **통과**: 기대와 같음 / **실패**: 다름(무엇이 달랐는지 비고에) / **못 봄**: 연결 전·기기 미지원·시간 부족
- 실패가 A·B 쪽 원인으로 보이면 비고에 `→A` 또는 `→B`를 붙입니다. C 표에서는 C가 받은 입력에 대해 C가 맞게 동작했는지를 따로 적습니다.

## 2. 시나리오별 표 (25개)

### 2-0. 이 표를 읽는 법 (모든 행에 공통인 C 동작)

- **선택 창이 뜨는 조건**: A가 `PopupEvent.Candidate`를 보내면 C는 B 분류를 받아 선택 창을 띄웁니다. A가 `Blocked`(민감 화면)·`Invalidated`를 보내면 선택 창을 닫고 띄우지 않습니다. ([근거 F1](#근거-목록)) A가 아무것도 보내지 않으면(감지 못 함) C도 아무것도 하지 않습니다.
- **누르기 버튼**(`'%s' 버튼 눌러 주기`, `ui_choice_press_candidate`)은 다음을 **모두** 만족할 때만 보입니다. ([근거 P1·P2](#근거-목록))
  1. B 분류가 `USER_DECISION`이 **아님**
  2. B 후보의 역할이 `CLOSE` 또는 `SKIP`, 근거가 `E1`·`E2`
  3. 버튼 이름이 공용 라벨 계약(`core/model/ButtonLabelRules`, #14, 허용 14개)에서 **후보와 같은 역할**: 닫기 `닫기`, `창 닫기`, `팝업 닫기`, `close`, `dismiss`, `광고 닫기`, `공지 닫기`, `닫기 버튼`, `close ad` / 건너뛰기 `건너뛰기`, `스킵`, `skip`, `skip ad`, `광고 건너뛰기` (NFKC·소문자·공백 정리 뒤 정확히 일치. `X`·`×`·`취소`·`확인`·`나중에`·`거부`·`오늘 하루 닫기`·`자세히 보기`·`설치`는 해당 없음)
  - 라벨이 허용돼도 **실행 허가가 아닙니다.** A 게이트가 최종입니다. 지금 A 게이트(`feature/a-action-gate`, main 미병합)는 아직 예전 8개 목록이라, 새로 늘어난 6개(`광고 닫기`·`공지 닫기`·`닫기 버튼`·`close ad`·`skip ad`·`광고 건너뛰기`)는 C가 버튼을 보여 줘도 A가 거부할 수 있습니다. 재현 앱 버튼은 `닫기`·`건너뛰기`뿐이라 이 표의 기대값에는 영향이 없습니다.
- **"이 팝업은 대신 닫을 수 없어요."**(`ui_choice_cannot_press`)는 누르기 버튼이 0개이고 B 분류가 `USER_DECISION`이 **아닐 때만** 화면에 보이고 읽힙니다. **B가 `USER_DECISION`으로 분류하면 이 문장은 나오지 않고** 대신 요약 `ui_choice_summary_review`("확인이 필요한 팝업이에요. 직접 확인해 주세요.")가 나옵니다. ([근거 P1·P4](#근거-목록))
- **요약 문장**(B 분류 → 문자열, [근거 P3](#근거-목록)):
  | B 분류 | 문자열 이름 | 문장 |
  |---|---|---|
  | `ADVERTISEMENT` | `ui_choice_summary_ad` | 광고로 보이는 팝업이에요. |
  | `NOTICE` | `ui_choice_summary_notice` | 공지로 보이는 팝업이에요. |
  | `USER_DECISION` | `ui_choice_summary_review` | 확인이 필요한 팝업이에요. 직접 확인해 주세요. |
  | `UNKNOWN` | `ui_choice_summary_unknown` | 팝업이 떴어요. |
- **선택지 순서**: [누르기 버튼들] → [내용 다시 읽기] → [그대로 두기]. ([근거 P1](#근거-목록)) 지금 꺼져 있어 **나오면 안 되는 것**: [버튼으로 이동], [앞으로 항상 눌러 주기], [다시 묻지 않기], 거부 이유 문장(`ui_policy_block_*`, `ui_label_reject_*`). ([근거 P5](#근거-목록))
  - **거부 이유 안내는 기능 플래그(`CannotPressReasonFeature`)가 꺼져 있어 지금은 나오지 않습니다.** 예를 들어 P04에서 "버튼 이름을 알 수 없어서…"가 들리면 플래그가 켜진 빌드이니 비고에 적습니다.
- **자체 음성 안내**(짧게, 기본): 창이 뜨고 0.7초 뒤 한 번 — `요약` (+ 누르기 버튼 0개이고 USER_DECISION이 아니면 `ui_choice_cannot_press`) + `ui_choice_where`("화면 아래 선택 창에서 고를 수 있어요."). 0.7초 전에 [말하기]를 누르면 이 안내는 건너뜁니다. "자세히"이면 그 사이에 `ui_choice_detail_press_buttons`(대신 누를 수 있는 버튼 이름)와 `ui_choice_detail_option_count`(선택지 개수)가 들어갑니다. ([근거 T1·T2](#근거-목록))
- **첫 통합(INT1)은 비실행입니다**(FIRST_INTEGRATION_CHECKLIST 1장). 이때 [누르기]를 고르면 결과는 `NOT_EXECUTED` → C는 `ui_result_not_pressed`("안전 확인을 통과하지 못해서 누르지 않았어요.")를 말하고 다시 누르지 않으며, **logcat 줄이 없어야 정답**입니다. "닫았어요"가 나오면 실패입니다. 아래 표의 "성공 시 … logcat `P01:btn_close`"는 실제 누르기를 켠 뒤의 기대값입니다.
- **누른 뒤 결과 안내**: 성공이면 2초 묶음 안내 `ui_announce_batch_closed`("팝업 1개를 닫았어요."). 실패면 `ui_result_*` 이유 + 다음 선택 문장, 다시 누르지 않음. ([근거 R1](#근거-목록)) "닫았어요"는 버튼을 눌렀다는 뜻일 뿐 사용자가 들었다는 뜻이 아닙니다.
- **음성 명령**([말하기]가 보일 때만, 한 번 누를 때 한 번만 들음, [근거 V1~V3](#근거-목록)):
  - **"닫아"** → `CLOSE`. 선택 창에 CLOSE 누르기 버튼이 **정확히 1개**면 그 버튼을 탭한 것과 같음(이후 B 정책·A 관문 재확인). 0개거나 2개 이상이면 `ui_choice_cannot_press`("이 팝업은 대신 닫을 수 없어요.")를 말하고 아무것도 안 함.
  - **"결제해"** → '결제'가 들어 있어 어떤 시나리오에서든 `ui_voice_refused`("그 버튼은 대신 누를 수 없어요.")만 말하고 아무것도 안 함. 들은 말을 되풀이하지 않음.
- **logcat 기대**: 선택 창에서 누르기 버튼을 골랐을 때만 `<ID>:btn_close`가 찍혀야 합니다. 선택 창이 뜨기만 하고 사람이 고르지 않았는데 줄이 찍히면 **실패(자동 클릭)**입니다.

> 아래 표에서 "누르기 버튼"의 이름은 재현 앱 화면 글자(`popup-test-app/src/main/res/values/strings.xml`)와 위 허용 라벨을 맞춰 본 **예상**입니다. 실제로 보이려면 A가 그 노드를 후보로 넘기고 B가 역할 CLOSE·근거 E2를 붙여야 합니다.
