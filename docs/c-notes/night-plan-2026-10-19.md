### 1. ⚠️ 라벨 표시 맞추기 (A 10/18 요청: "실행 가능하다고 잘못 안내하지 않도록")
- A 실행 게이트가 **받아 주는 라벨일 때만** 누르기 버튼을 보여 준다. 그 외(X, ×, 라벨 없는 DISMISS, 확인/OK 등)는 누르기 버튼 없이 "이 팝업은 대신 닫을 수 없어요" + (3단계 준비되면) [버튼으로 이동] 안내.
- A 게이트의 허용 라벨(10/18 기준): `닫기 / 창 닫기 / 팝업 닫기 / close / dismiss / 건너뛰기 / 스킵 / skip`. 합의 예정 추가: `광고 닫기 / 공지 닫기 / 닫기 버튼 / close ad / skip ad / 광고 건너뛰기`(정확 일치). **A 코드에서 실제 목록을 읽어 확인**하고 그대로 따른다.
- 판정은 `ChoicePromptPlanner`에 **주입 가능한 정책**(예: `PressableLabelPolicy`)으로 분리. 지금은 C 임시 복사본임을 주석·보고서에 명시하고, **공용 계약 함수가 생기면 그것으로 바꿀 자리**를 표시한다.
- **B 공용 라벨 판정 계약 초안 v1(10/19, 준영)**: `ButtonLabelRules.roleOf(label)`(NFKC → 소문자 → 공백 정리 → 위험 단어 → 정확 일치), 허용 14개(+Q2 붙여 쓴 6개). 계약 PR 병합 뒤 C는 `roleOf(label) == candidate.role`로 교체 예정(초안 11절). **오늘 밤은 A 게이트의 현재 8개 기준 임시 정책**으로 만들고, 정책 인터페이스가 `roleOf` 형태(라벨 → CLOSE/SKIP/없음)와 맞게 설계. 원본 문서: `C:\Users\jaeho\Downloads\닫아줄게_공용라벨판정_계약초안_v1.md`, 시험 사례 `label_test_vectors.csv`(175개) — 임시 정책 시험에 A 현재 기준 열(`a_current`)을 활용.

### 2. 누르기 실패 안내
- 실행 결과(`ActionResult`)가 성공이 아니면(BLOCKED/STALE/NOT_EXECUTED/ATTEMPT_FAILED/OUTCOME_UNKNOWN) 사용자에게 알리는 문장과 다음 선택 안내(다시 읽기 / 그대로 두기 / 준비되면 버튼으로 이동). "닫았어요"라고 말하지 않는다.
- `AnnouncementBatcher`의 결과 분류와 일관되게. Mock 결과로 시험. 미리보기에서 "실패 결과 흉내" 확인 경로.

### 3. [버튼으로 이동] 준비 (계약 전이라 꺼 둔 상태)
- 합의 내용: `MOVE_TO_BUTTON`은 **사용자가 직접 찾도록 안내·이동**이지 자동 클릭 허가가 아니다.
- 계약에 값이 없으므로 C 내부에 **기능 플래그(기본 꺼짐)**로 UI·음성 명령 연결만 준비. 계약 값이 생기면 플래그만 켜면 되게. 실제 포커스 이동은 A(서비스) 몫 — C는 요청 인터페이스 초안만.

### 4. 안내 길이(짧게/자세히) 반영
- 설정값을 선택 창 등장 TTS·묶음 안내 문장에 반영. "자세히" = 요약 + 분류 근거 없이 **확인된 정보만**(예: 버튼 이름, 팝업 개수). 단정하지 않는 표현 유지. 시험 추가.

### 5. TTS 상태 계약 초안 문서 (`docs/c-notes/contract-proposal-tts-2026-10-19.md`)
