# 중간 발표(10/28) C 부분 자료 — UI·TalkBack·음성 (재호)

> 발표자 우진이 읽기 쉽게 쓴 자료. 숫자는 보고서·실험 문서(`docs/experiments/overlay-talkback.md`, `docs/c-notes/*-report-*.md`)에 있는 것만 썼다.
> 10/20 기준. **실제 팝업 감지(A)·분류(B)·저장소(D)와 아직 연결 전이라, 시연은 가짜 팝업(Mock)으로 한다.**

## 1. C가 맡은 것 (한 줄)

팝업을 찾았을 때 **사용자에게 알려 주고(TalkBack·음성), 사용자가 직접 고르게 하는(선택 창·음성 명령·설정) 부분**을 맡았다.

## 2. 화면 흐름

```
[다른 앱에 팝업]                         (A: 감지)
      │
      ▼
[분류·안전 판단]                         (B)
      │
      ▼
┌──────────── 닫을까요? (C) ─────────────┐
│ "광고로 보이는 팝업이에요."              │ ← 0.7초 뒤 앱이 소리로 요약 안내
│ ['닫기' 버튼 눌러 주기]                 │ ← A 관문이 받는 라벨만 버튼으로 보임
│ [내용 다시 읽기]  [그대로 두기]           │
│ [말하기]  [다시 듣기]  [그만 말하기]      │ ← [말하기]는 누를 때만 마이크 켬
└─────────────────────────────────────────┘
      │ 탭 또는 음성 ("닫아")  ← 둘 다 같은 길
      ▼
[B 정책 → A 실행 관문에서 다시 확인 후 누르기]
      │
      ▼
[결과 안내] "닫았어요" / 실패면 이유와 다음 선택 (C)
```

- 선택 창은 다른 앱 위에 화면 아래쪽으로 뜨는 접근성 오버레이다.
- 설정 화면: 앱별 자동 닫기(기본 꺼짐), 안내 길이(짧게/자세히), 선택 창 음성 안내, 음성 명령 켜기/끄기, 기억한 팝업 해제.

## 3. 안전 장치

| 장치 | 내용 |
|---|---|
| 포커스를 뺏지 않음 | 선택 창은 TalkBack 포커스를 스스로 옮기지 않는다. 사용자가 쓸어서 찾아간다. |
| 명령어 오인 방지 | 마이크는 [말하기]를 누를 때만 켠다. 누르면 우리 안내 소리를 먼저 멈춘다. 첫 안내 전에 [말하기]를 누르면 그 안내는 건너뛴다. 마이크가 켜진 동안 읽히는 문장에는 "닫아" 같은 명령어를 넣지 않았다(시험으로 고정). 영상 소리·옆 사람 말이 명령으로 들어가는 것을 막기 위해서다. |
| 결제·동의는 안 누름 | 결제·구매·구독·삭제·권한·동의·로그인은 음성이든 탭이든 대신 누르지 않는다. 중요 결정 팝업에는 누르기 버튼 자체가 없다("직접 확인해 주세요"). |
| 라벨 허용 ≠ 실행 | 선택 창에 버튼이 보여도, 실제로 누르기 직전에 B 정책과 A 실행 관문이 화면과 버튼을 다시 확인한다. 음성도 같은 길이다. |
| 반복 자동화는 꺼 둠 | "앞으로 항상 닫기"는 기능 플래그로 꺼 두었다. 저장소(D) 연결 뒤에도 매번 같은 팝업인지 다시 검사해야만 켠다. |
| 화면 글자 비저장 | 팝업 글자, 들은 말은 로그·파일에 남기지 않는다. INTERNET 권한 없음. |

## 4. 확인한 것 / 아직 Mock인 것 (정직하게)

**실기기(LG 벨벳, Android 12, TalkBack 17)에서 확인한 것**
- 선택 창 미리보기를 TalkBack으로 읽고 고를 수 있음, 중요 결정 팝업에 닫기·동의 버튼 없음 (10/17)
- 다른 앱(홈 화면) 위에 선택 창이 뜨고, 누르기·내용 다시 읽기가 됨 (10/18)
- TalkBack은 새로 뜬 오버레이 창의 제목을 스스로 읽지 않음 → 그래서 앱이 직접 소리로 알린다. 0.7초·1.5초 모두 4번 중 4번 끝까지 들렸고, TalkBack이 우리 안내를 끊지 않았다 (10/18)
- 글꼴 2.0배·다크 모드에서 선택 창이 잘리지 않고 읽힘, [말하기]는 기기 미지원이라 숨겨짐 (10/20, 화면만 확인)

**아직 Mock·미검증인 것**
- 실제 팝업 감지(A)·분류(B)·저장소(D)와의 연결 → 가짜 팝업 데이터로만 확인
- 음성 명령 실제 인식: LG는 기기 안 음성 인식 미지원 → 갤럭시 S26에서 확인 예정

## 5. 시연 (LG, 3~5분)

준비(발표 전): 노트북에 LG 연결, debug 빌드 설치, 폰 설정 → 접근성에서 **"닫아줄게 C 선택 창 시험"** 켜기, 필요하면 TalkBack 켜기. 소리 크게.

| 순서 | 할 일 | 보여 줄 것 |
|---|---|---|
| 1 (1분) | 광고 팝업: 아래 명령 후 바로 홈 버튼 | 5초 뒤 홈 위에 "닫을까요?" 창 + "광고로 보이는 팝업이에요…" 소리 |
| 2 (1분) | [내용 다시 읽기] → ['닫기' 버튼 눌러 주기] | 내용 낭독, 버튼 이름을 말해 주고 고르는 방식 |
| 3 (1분) | 중요 결정(결제 동의) 시나리오 3 | 누르기 버튼이 없음 + "직접 확인해 주세요" |
| 4 (1분) | 설정 화면 | 자동 닫기 기본 꺼짐, 안내 길이, 음성 명령 구역 |
| 5 (선택) | 닫기·건너뛰기 둘 다 있는 시나리오 6 | 버튼 이름으로 구분해서 보여 줌 |

```bash

```

```bash

```


- 시나리오 번호: 0 광고, 1 공지, 2 날짜 바뀐 공지, 3 중요 결정, 4 라벨 없는 버튼, 5 영상(광고 여부 미확인), 6 닫기·건너뛰기 둘 다.
- 설정 화면은 미리보기가 이미 떠 있으면 안 열리므로 `-S`(새로 시작)를 붙인다.
- 끝나면 C 시험 서비스(와 TalkBack)를 꺼 둔다.
- 음성 명령은 LG에서 시연할 수 없다(기기 미지원). 말로만 설명한다.

## 6. 예상 질문과 답

1. **음성 명령이 TalkBack 소리나 영상 소리를 명령으로 잘못 들으면?**
   [말하기]를 누를 때만 듣고, 누르면 우리 안내를 멈춘다. 결제·동의 같은 말은 명령으로 받지 않고, 알아들은 명령도 탭과 똑같이 B·A의 안전 확인을 다시 거친다.
2. **왜 팝업을 바로 닫지 않고 묻나요?**
   처음 보는 팝업을 광고처럼 보인다는 이유만으로 누르면, 결제·동의 버튼을 잘못 누를 수 있다. 사용자가 고르게 하고, "앞으로 항상"은 사용자 허락 + 같은 팝업 재검사가 모두 될 때만 하도록 설계했다(지금은 꺼 둠).
3. **TalkBack이 이미 읽어 주는데 왜 앱이 따로 말하나요?**
   LG 실험에서 TalkBack은 새로 뜬 오버레이 창의 제목을 스스로 읽지 않았다. 그래서 앱이 0.7초 뒤 짧게 직접 알린다. 설정에서 끌 수 있다.
4. **실제 앱 팝업에서도 되나요?**
   아직 아니다. 감지(A)·판단(B)과 연결 전이라 가짜 팝업으로만 확인했다. 연결 부품(`PopupChoiceFlow`)은 준비돼 있고, 연결 후 실기기 검증 예정이다.
5. **개인정보는요?**
   팝업 글자와 들은 말은 저장·로그하지 않고, 인터넷 권한이 없어 밖으로 보내지 않는다. 음성 인식도 기기 안 인식만 쓴다.
