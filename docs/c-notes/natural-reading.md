## ① 낭독 변환 `SpeakableText` (`ui/voice/SpeakableText.kt`)

원칙: 팝업 글을 **요약·바꿔 말하기 없이 그대로** 읽는다. TTS가 기호·형식을 어색하게 읽는 것만 읽기 좋은 말로 바꾼다. 화면 글자는 그대로, **낭독 문자열만** 바뀐다. 숫자 자체("12,900원")는 TTS가 잘 읽으므로 건드리지 않는다. 입력·출력 모두 화면 글자라 로그에 남기지 않는다.

| 규칙 | 전 | 후 |
|---|---|---|
| 시간 범위(24시간제 근거 있음) | `02:00~04:00` | 오전 2시부터 오전 4시까지 |
| | `10:00~18:30` | 오전 10시부터 오후 6시 30분까지 |

| 시간 하나 | `14:30 시작`, `02:00 점검`, `오후 2:30`, `PM 7:00` | 오후 2시 30분 시작 / 오전 2시 점검 / 오후 2시 30분 / 오후 7시 |

| 해시태그 | `안심직구 베스트 #디지털 #패션 #잡화` | 안심직구 베스트, 디지털, 패션, 잡화 |

| 바꾸지 않음 | "앱에서만 제공되는 혜택을 놓치고 계신 건 아닌가요?", "0분 15초 중 0분 15초", "12,900원" | (그대로) |

24시간제 판단: 한 표현 안에 0시·13~23시·앞에 0이 붙은 시("02")가 하나라도 있으면 그 표현의 모든 시각에 오전/오후(12시는 "낮 12시")를 붙인다. 아니면 "N시"만. 날짜는 연도·요일·`/`+두 자리 월/일이 있을 때만 날짜로 본다.

넣는 말("부터", "퍼센트", "웹 주소" …)은 문자열 리소스가 아니라 `SpeakableText.Words` 상수 표에 둔다. 화면 문장이 아니라 바로 옆 규칙과 짝인 **TTS 읽기 단위**라서, 번역하려면 규칙도 같이 바뀌어야 하기 때문이다(코드에 이유 주석).

### 적용 위치 (C가 팝업 원문을 TTS로 읽는 곳 전부)

| 곳 | 코드 |
|---|---|
| 선택 창이 뜰 때 원문 낭독(TalkBack 주도권) | `TalkBackTakeoverPlan.speech` — 원문 줄 끝 쉼, 우리 안전 문장 앞에도 쉼 |
| [내용 다시 읽기] | `PromptSpeech.content` (A가 `PopupChoiceFlow`의 `contentText`로 넘기는 함수) |
| 자동 처리 ANNOUNCE의 내용 | `SpeechHandlingListener` — A가 넘긴 `contentOf` 결과에 적용 |
| "'제목' 광고를 닫았어요"의 제목(지금 꺼짐) | `SpeechHandlingListener.spokenTitle` — `SpeakableText.inline`(줄을 공백으로) 뒤 20자 자르기 |

변환 결과가 비면(장식만 있는 글) "읽을 수 있는 글자가 없어요" 또는 기존 짧은 안내로 대신한다.

## ② 긴 닫기 이름 짧게 보여 주기 `ButtonNameDisplay` (`ui/voice/choice/ButtonNameDisplay.kt`)

선택 창 버튼 "'○○' 버튼 눌러 주기"·"'○○' 버튼, 앞으로 항상 눌러 주기"의 ○○:

| 버튼 이름(정규화 후) | 역할 | 보이는 이름 |
|---|---|---|
| 8자 이하이고 역할 낱말(닫기·close·dismiss / 건너뛰기·스킵·skip)이 들어 있음: 닫기, 광고 닫기, 닫기 버튼, Close, close ad, skip ad, 광고 건너뛰기 … | CLOSE/SKIP | **그대로** |
| 그 밖: "앱설치 안내 레이어 닫기"(13자), "모바일 웹으로 볼래요", "웹으로 볼게요"(역할 낱말 없음) | CLOSE | **닫기** (`ui_choice_role_close`) |
| "5초 후 광고 건너뛰기" | SKIP | **건너뛰기** (`ui_choice_role_skip`) |
| [버튼으로 이동](꺼짐), 다른 역할 | — | 그대로 (사람이 찾아가야 하므로 원래 이름) |

- **원래 이름은 사라지지 않는다.** [내용 다시 읽기] 끝에 "'닫기' 버튼은 화면에 '앱설치 안내 레이어 닫기'라고 쓰여 있어요."(`ui_content_button_real_name`)를 붙인다. 팝업 글에 이미 그 이름이 있으면 붙이지 않는다. 안내 길이 "자세히"도 원래 이름을 읽는다.
- **보이는 이름만 바뀐다.** 누를 수 있는지는 그대로 `SharedLabelPolicy`(= core `ButtonLabelRules.roleOf`) → B 정책 → A 게이트가 정한다. 짧게 보여 주기가 누를 수 있는 버튼을 늘리지 않는다.
- `UserChoice`는 그대로 `buttonMeaningConfirmed = true`: 버튼 역할("닫기")을 보고 골랐고, 원래 이름은 [내용 다시 읽기]로 확인할 수 있다.

### 연결 지점 (core v2)

- 지금 core v1(허용 14개)은 "앱설치 …"(설치 → NAVIGATION_WORD)·"웹으로 볼래요"(목록에 없음)를 둘 다 거부한다 → 지금은 누르기 버튼 자체가 안 생기고, **화면에서 바뀌는 것이 없다**(시험: v1 허용 14개는 모두 그대로).
- B 준영의 v2(v2-a "○○ 닫기", v2-b "웹으로 볼래요/볼게요")가 `ButtonLabelRules`에 들어오면 `SharedLabelPolicy`가 자동으로 그 버튼을 보여 주고, `ButtonNameDisplay`가 "닫기"로 줄인다. **C 코드 수정 없음.**
- v2가 core 대신 별도 함수로 들어오면 `SharedLabelPolicy.roleOf` 한 곳만 그 함수로 바꾼다.
- C는 v2 판정 규칙을 따로 만들지 않는다(core 수정 금지, 판정은 공용 계약 하나).

## 미검증·남은 것

- LG(Android 12) TTS가 "."·줄바꿈에서 실제로 쉬는지, "원 플러스 원"·"웹 주소"가 자연스러운지.
- TalkBack이 직접 읽는 화면 글자(우리 TTS가 아님)는 바뀌지 않는다. 다른 앱 화면은 C가 못 바꾼다.
- "05:30"처럼 두 자리로 쓴 영상 길이는 시각으로 읽힐 수 있다(드묾, 실제 사례 나오면 규칙 조정).
