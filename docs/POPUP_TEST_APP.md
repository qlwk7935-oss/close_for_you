# 팝업 재현 앱·웹 페이지 (D)

담당: 동준/D, 브랜치 `feature/database-qa`. 검증 실험 계획의 A03(정답지), A05(위험 화면), B03(라벨 없는 버튼), C01·C03~C09에서 같은 화면을 반복 재현하려고 만든 **합성 시험 도구**입니다.

- 모든 문구·금액·날짜는 가짜입니다. 실제 결제·권한·로그인·네트워크 동작은 하지 않습니다.
- 정답지는 사람이 정한 **평가 기준**입니다. 닫아줄게의 감지·분류·클릭 성능 결과가 아닙니다.
- 기존 `:capture-test-host`(A, 캡처·OCR 계측용)와는 별개입니다. 본 앱 `:app`과 서로 의존하지 않습니다.
- **상태: 미검증.** 이 문서를 작성한 환경에서는 빌드·실기기·TalkBack 시험을 하지 못했습니다. CI 결과와 실기기 시험은 [개발 상태](DEVELOPMENT_STATUS.md)에 따로 기록합니다.

## 실행

```bash
./gradlew :popup-test-app:assembleDebug :popup-test-app:testDebugUnitTest
adb install -t popup-test-app/build/outputs/apk/debug/popup-test-app-debug.apk
```

testOnly 앱이라 `adb install -t`가 필요합니다. 앱을 열면 시나리오 목록이 나옵니다. 특정 시나리오를 바로 열려면:

```bash
adb shell am start -n kr.closeforyou.popuptest/.PopupScenarioActivity --es scenario P04
```

닫아줄게 본 앱에서 분석하려면 본 앱의 앱별 허용 목록에 `kr.closeforyou.popuptest`를 직접 추가해야 합니다(초기 목록은 비어 있음).

### 쿠폰·프리셋 목표·첫 통합 예상 (10/25)

- **쿠폰**(`COUPON`): 받거나 가진 혜택(쿠폰·포인트 지급 등). 계약 v2 `PopupClassification.COUPON`과 같은 뜻입니다. P01·P12(첫 창)·P13은 "가을 할인 쿠폰", P02는 "가입하면 포인트를 드립니다"입니다.
- **프리셋 목표**(`preset_close_all`·`preset_close_ads_and_coupons`·`preset_close_ads_only`): 프리셋을 고르고 자동 닫기에 동의한 뒤의 목표입니다. 사람 기준 종류에 C `HandlingPreset`을 적용합니다(`CLOSE`·`ANNOUNCE`·`ASK`·`BLOCK`·`NONE`). 닫기가 목표여도 앱 허용 버튼이 없거나(P04·P05·P13) 건너뛰기뿐이면(P16, 자동 건너뛰기 OFF #46) `ASK`입니다. 지금은 자동 닫기가 꺼져 있어 실제로는 모두 선택 창으로 묻습니다.
- **첫 통합 예상**(`int1_kind`·`int1_path`): 지금 A·B 코드로 예상되는 분류와 경로입니다. `TREE`는 트리 글자 그대로 B 분류, `A_SUMMARY`는 A 결정 요약, `A_BLOCK`은 A 민감 화면 차단입니다. 앱 모듈 `AnswerKeyPipelineTest`가 A `PrivacyPolicy`·`DecisionEvidence`와 B `DecisionPopupClassifier`로 CI에서 다시 계산해 대조합니다. **실기기 결과가 아니며** 감지(F1)·후보 찾기·OCR은 포함하지 않습니다.

사람 기준과 첫 통합 예상이 다른 칸입니다. 실측에서 이대로 나오면 `known_limit=Y`로 적습니다.

**재현 앱 문구 정리 (10/25)**: 시험 문구가 의도와 다른 이유로 A에 걸리던 곳을 고쳤습니다. 코드로 계산한 결과이며 실측 확인은 아직입니다.

- 공지(N01~N06·N08, P07 그림, P12 둘째 창, 웹 W05): "결제 기능" → "주문 기능". '결제'가 있으면 A가 결정 요약으로 바꿔 공지로 분류되지 않고, 공지 기억 시험(C05·C09)이 성립하지 않습니다. 결제 문구 한계는 P18이 맡습니다.
- N07: "개인정보 처리방침" → "이용약관". '개인정보'는 A가 민감 화면으로 막습니다.
- P04 본문, 웹 W02: "이름 없는" → "글자 없는". '이름'은 A가 민감 화면으로 막습니다.
- 화면 제목: "P02 같은 창 덮개 광고" → "P02". 같은 창의 제목 글자까지 분석에 들어가면 P07은 공지, P12는 결정으로 바뀝니다.
- 웹 페이지: 팝업이 떠 있는 동안 시나리오 목록(W01~W08)을 숨깁니다. 목록의 '결제'·'동의'·'이름' 때문에 P13이 결정 또는 차단으로 나올 수 있었습니다(A 승인 10/25). 실제 앱처럼 뒤 페이지에 위험 문구가 있는 경우는 **P24**(웹 `#ad-risky-back`, W08)로 안전 차단을 따로 확인합니다.

**세 가지를 따로 적습니다**: 사람 기준 종류(`kind`, 예: P01·P12·P13 쿠폰), 프리셋 목표(`preset_*`, 사람 기준으로 정한 목표), 실제 서비스 실행 가능 여부(시행 기록 `auto_executable`). 목표가 CLOSE여도 실행할 수 없는 상태면 묻는 것이 정상입니다.

### 자동 닫기 시나리오 (P19~P23, 10/25 추가)

- **P19 (S16 가짜 닫기)**: 라벨이 '닫기'인 버튼이 팝업을 닫지 않고 홈 화면으로 나갑니다(`btn_fake_close`, 기록 `left_app`). 네트워크·다른 앱 조작은 없습니다. 진짜 닫기는 뒤로 가기뿐입니다.
- **P20 (S17 연속 광고)**: '닫기'로 닫으면 1초 뒤 다른 광고가 나옵니다(4개). 뒤로 가기로 닫으면 멈춥니다.
- **P21·P22 (S18 사기 의심)**: "1등 당첨"·"휴대폰 감염" + 사기 행동 버튼(광고 페이지로 이동) + '닫기'. 앱은 어느 버튼도 누르면 안 됩니다.
- **P23 (S20 늦은 닫기)**: 3초 동안 누를 버튼이 없다가 '닫기'가 생깁니다.
- S14·S15·S19는 P01, S20의 건너뛰기는 P16을 씁니다.

### 영상·건너뛰기 (P16~P18, 10/22 추가)

- **P16**: 전체 화면 영상 광고(합성). 가운데에 **빈 영상 표면** `VideoView`(리소스 ID `video_surface`, 재생 소스 없음)가 있고, "재생 중 0:03"이 매초 바뀌며, 오른쪽 아래 "N초 후 건너뛸 수 있어요"가 5초 동안 줄어든 뒤 `btn_skip`(건너뛰기)이 생깁니다. 카운트다운 중에는 누를 버튼이 없으므로, 그때 건너뛰기를 제안하면 오류입니다.
  - 영상 표면 관측 확인: `adb shell uiautomator dump /sdcard/p16.xml && adb shell cat /sdcard/p16.xml | grep -o 'id/video_surface"[^>]*class="android.widget.VideoView"'` — 한 줄이 나오면 접근성 트리에 표면 노드가 보이는 것입니다. 실측 결과는 아직 없습니다.
  - **한계**: 빈 표면이 보인다는 것은 영상 재생·영상 광고 판정의 증거가 아닙니다. A는 아직 영상 신호(`videoSurfaceObserved`)를 채우지 않습니다. P16은 Dialog 없는 앱 자체 덮개라 현행 A/F1에서 후보가 0일 수 있습니다(P02·P03과 같은 한계, 실기기 체크리스트 P8).
  - `VideoSurfaceFixtureTest`는 표면 뷰가 코드에서 빠지지 않았는지만 정적으로 확인합니다.
- **P17**: 라벨 있는 버튼이 둘(건너뛰기·닫기). 건너뛰기는 두 번째 광고를 열고 닫기만 광고를 끝냅니다. 건너뛰기는 금지 버튼은 아니지만 앱 허용 버튼도 아니어서, 앱이 누르면 오클릭으로 셉니다. F12 기억은 닫기에만 맞아야 합니다(후보 여러 개, B 리뷰 10/21).
- **P18**: 타임세일 종료 카운트다운(매초 변경)과 "5초 안에 결제" 문구가 있지만 건너뛰기와 무관합니다. B가 이 시간 문구를 건너뛰기 카운트다운으로 보면 오인입니다(B #20, A 리뷰 10/22).
- P16·P18은 글자가 시간에 따라 바뀌어 같은 화면으로 기억할 수 없으므로 기억 가능 "아니오"입니다.

### 공지 변형 (C05·C09)

### 앱 업데이트·버튼 위치 변경 (C09, 10/25 추가)

F12 기억은 앱 버전과 대상 버튼(라벨·위치 등)까지 묶어 지문을 만듭니다. 그래서 아래 두 경우 모두 **이전 기억으로 자동 처리하면 실패**이고, 처음 본 공지처럼 다시 선택 창이 떠야 합니다. 실측 결과는 아직 없습니다.

**버튼 위치만 변경 (N08)**: N01과 글자가 같고 닫기 버튼만 제목 위로 옮긴 공지입니다.

1. N01을 열고 C 선택 창에서 기억하기를 고릅니다(기억 저장이 연결된 빌드에서만 의미 있음).
2. N02를 열어 기억이 맞는지 봅니다(맞아야 정상).
3. N08을 엽니다. 기억이 맞으면 **실패**입니다.

**앱 버전 변경**: 같은 화면을 재현 앱 버전만 올려 다시 엽니다.

```bash
./gradlew :popup-test-app:assembleDebug                            # versionCode 1
adb install -r -t popup-test-app/build/outputs/apk/debug/popup-test-app-debug.apk
# N01 열고 기억하기 → N02에서 기억이 맞는지 확인
./gradlew :popup-test-app:assembleDebug -PpopupTestVersionCode=2   # versionCode 2
adb install -r -t popup-test-app/build/outputs/apk/debug/popup-test-app-debug.apk
adb shell dumpsys package kr.closeforyou.popuptest | grep versionCode   # 2인지 확인
# N02를 다시 엶 → 기억이 맞으면 실패
```

- 버전 1의 옛 기억은 목록에 남아 있다가 만료(최대 30일) 뒤 정리됩니다. 지우지 않았다고 실패가 아닙니다.
- `popupTestVersionCode`는 1 이상의 정수만 받습니다(아니면 빌드 실패). 끝나면 기본(1)으로 다시 설치해 둡니다.
- 결과 CSV는 `scenario_id`를 N02로, `notes`에 `버전 2`를 적습니다.
