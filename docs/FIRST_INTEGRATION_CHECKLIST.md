# 첫 통합 실측 검증표 (D)

담당: 동준/D. 우진(A)의 첫 통합 실측(Android Studio API 37 에뮬레이터)을 같은 기준으로 기록·집계하기 위한 표입니다. C 화면·TalkBack 세부는 재호의 `docs/c-notes/c-test-checklist.md`를 함께 씁니다.

**이 문서는 빈 표입니다.** 아직 아무 실측도 하지 않았습니다. 확인하지 않은 칸은 "통과"로 채우지 않고 **못 봄**으로 둡니다.

## 1. 이번 실측의 목표와 금지

목표: **안전한 팝업 감지 → 분류 → 사용자 안내 → 명시적 선택 → 비실행 결과**까지 확인합니다(A 10/22).

| 반드시 0건 | 확인 방법 |
|---|---|
| 앱이 실제로 누른 버튼(클릭·제스처·자동 닫기) | **측정 구간** logcat에 재현 앱 버튼 기록 0줄, `qa_metrics.py --no-click` 판정 **통과(검증됨)** |
| 광고 페이지 도착(`ad_landing_opened`) | logcat |
| 위험 화면(P08~P11)에서 누르기 버튼 제안 | C 선택 창 확인, `offered_press=N` |
| 민감 화면(P11) 분석·안내 | 선택 창·자체 TTS 없음, A 차단 |
| 화면 원문이 로그에 남음 | `adb logcat` 전체에서 재현 앱 문구(예: "가을 할인 쿠폰") 검색 시 0건 |

- 실제 클릭이 없으므로 사용자가 [누르기]를 골라도 결과는 **비실행**(`NOT_EXECUTED`)이어야 합니다. "닫았어요"라고 말하면 실패입니다.
- F9 `productionReady=false`, 자동 반복 OFF(`RepeatAutomation.EXECUTION_ENABLED=false`), F12 기억 저장은 연결하지 않은 상태가 전제입니다.

## 2. 준비

```bash
./gradlew :app:assembleDebug :popup-test-app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -t popup-test-app/build/outputs/apk/debug/popup-test-app-debug.apk
```

1. 닫아줄게 접근성 서비스 켜기, 앱별 허용 목록에 `kr.closeforyou.popuptest` **직접** 추가(초기 목록은 비어 있음).
2. TalkBack은 사람이 설정에서 켭니다(에뮬레이터 TalkBack 결과는 참고용, "통과"는 실기기만).

### 측정 구간 (시행 한 번마다)

logcat에는 누가 눌렀는지 남지 않습니다. 그래서 **시험자가 재현 앱을 만지지 않는 구간만** 저장하고, 그 구간에 기록이 한 줄이라도 있으면 원인과 상관없이 실패로 봅니다.

```bash
adb logcat -c
adb logcat -s PopupTest > int1_P01_1.log &          # ① 저장 시작
adb shell am start -n kr.closeforyou.popuptest/.PopupScenarioActivity --es scenario P01
# ② 관찰: 감지·선택 창·안내. C 선택 창에서 [누르기]를 골라 비실행 결과까지 확인
kill %1                                              # ③ 저장 끝 (재현 앱을 만지기 전에)
# ④ 그다음에 시험자가 뒤로 가기 등으로 팝업을 닫음 (저장 구간 밖)
```

- 측정 구간 안에서는 재현 앱 화면을 누르지 않습니다. C 선택 창 버튼은 눌러도 됩니다(재현 앱 기록이 남지 않음).
- 실수로 구간 안에서 재현 앱을 눌렀으면 그 시행은 버리고 다시 합니다.
- 모든 시행이 끝나면 `cat int1_*.log > popuptest.log`로 합쳐 집계에 넣습니다.
- 같은 절차를 `bash tools/int1_session.sh P01 1`로 할 수 있습니다(①~③을 대신하고 `int1_logs/`에 저장, Enter로 구간 끝, 기록이 있으면 경고). Windows는 Git Bash에서 씁니다.

## 3. 기록

[`templates/experiment_results.csv`](templates/experiment_results.csv)에 시행 한 번당 한 줄. `experiment_id`는 `INT1`.

| 열 | 이번 실측에서 |
|---|---|
| `detected` | A가 팝업으로 감지해 C 선택 창이 떴는지 Y/N |
| `outcome` | 선택 창에서 [누르기]를 골랐으면 `NOT_EXECUTED`, 안내만 했으면 `ANNOUNCED_ONLY`, A가 막았으면 `BLOCKED`, 감지 못 했으면 `MISSED` |
| `offered_press` | C가 누르기 버튼(`'닫기' 버튼 눌러 주기` 등)을 보여 줬는지 Y/N |
| `known_limit` | 아래 4-1의 "현재 예상(알려진 한계)"대로 나왔으면 Y. 잘못 거부·누르기 제안률에서 빼고 따로 보고합니다 |
| `clicked_target` | **비워 둡니다.** 이번 단계에 앱이 누른 버튼은 없어야 합니다 |
| `observed_kind` | 관측한 B 화면 분류(`COUPON`·`ADVERTISEMENT`·`NOTICE`·`USER_DECISION`·`UNKNOWN`, A가 막았으면 `BLOCKED`). 정답지 `int1_kind`와 대조합니다. 사람 기준 종류(예: P01·P12·P13 쿠폰)와는 따로 봅니다 |
| `preset` | 켠 프리셋. 첫 통합은 `OFF` |
| `auto_executable` | 그 시행에서 서비스가 실제로 자동 실행할 수 있었는지 Y/N. 첫 통합은 `N`. 프리셋 목표(정답지 `preset_*`)와 따로 적습니다 |
| `notes` | 화면 원문 없이. 예: "TTS 0.7초 뒤 1회", "사람이 뒤로 가기로 닫음" |

집계:

```bash
python3 tools/qa_metrics.py int1_results.csv --logcat popuptest.log --no-click
```

`--no-click` 판정은 셋 중 하나입니다.

| 판정 | 종료 코드 | 조건 |
|---|---|---|
| **실패** | 1 | 결과 CSV에 `AUTO_HANDLED`·`USER_CONFIRMED` 행, 또는 측정 구간 logcat에 재현 앱 버튼 기록(`ad_landing_opened` 포함) 1줄 이상 |
| **미검증** | 2 | `--logcat`을 주지 않음. "클릭 0건"이라고 주장할 수 없습니다 |
| **통과(검증됨)** | 0 | 위 둘 다 아님 |

이 단계에서는 "잘못 거부" 대신 **누르기 제안률**과 **잘못 제안**(앱 허용 버튼이 없는데 누르기 버튼을 보여 줌)을 봅니다. 회귀 시험: `python3 -m unittest discover -s tools -p "test_*.py"`.

### 4-1. 현재 예상과 목표가 다른 칸 (알려진 한계)

B가 API 37 에뮬레이터에서 #26 화면으로 확인한 결과(준영 10/22)입니다. **현재 예상대로 나오면 실패가 아니라 `known_limit=Y`로 기록**하고, 목표 미달로 따로 보고합니다. 통과시키려고 안전 정책(보수적 거부)을 완화하지 않습니다.

| ID | 현재 예상(알려진 한계) | 목표 | 이유 | 이 칸의 실패 |
|---|---|---|---|---|
| P16 | 누르기 버튼 **없음**(`ANNOUNCED_ONLY` 또는 `MISSED`). B R1과 관계없이 같음 | 카운트다운이 끝난 뒤 ['건너뛰기'] | 앱이 직접 그린 덮개라 Dialog 노드가 없어 현행 A/F1이 후보를 못 잡음(실기기 체크리스트 P8 한계). 영상 표면 신호(`videoSurfaceObserved`)는 A가 아직 채우지 않음 | 카운트다운 중 ['건너뛰기'] 제안, 앱이 누름 |
| P18 (A 결정 요약 영역 제한 연결 **전**, 첫 통합 기준) | 누르기 버튼 **없음**(`ANNOUNCED_ONLY`) → `known_limit=Y` | ['닫기']만 | 본문 "5초 안에 결제하면"의 '결제' 때문에 A가 B에 넘기기 전에 글자를 고정 결정 요약("결제 선택 필요")으로 바꾸고 노드를 비움(`DecisionEvidence.summarize`). 그래서 B는 결정으로 분류하고 후보가 없음. **B R1 병합만으로는 바뀌지 않음**(준영 B 시나리오 시험 10/25) | ['건너뛰기'] 제안(시간 문구를 카운트다운으로 오인), 앱이 누름 |
| P18 (A·B 팝업 영역 계약 7번 연결 **후**) | **목표**: B 분류 "광고", ['닫기']만. 연결·실측 전에는 결과 미확정이며 이 줄은 연결 PR에서 확정 | ['닫기']만 | 결정 요약이 팝업 범위로 좁혀지면 B가 원래 글자로 판단("타임세일" → 광고, B 정책 6종류 기준) | 위와 같음. ['닫기'] 미표시는 이 줄이 확정된 뒤에만 잘못 거부로 셈 |

**정답지 첫 통합 예상 (10/25)**: [정답지](templates/popup_answer_key.csv)의 `int1_kind`·`int1_path`가 지금 코드로 예상되는 분류입니다(CI `AnswerKeyPipelineTest`가 대조, 실기기 결과 아님). 사람 기준과 다른 P02(결정)·P03(모름)·P05(모름)·P07(모름)·P18(결정)은 그대로 나오면 `known_limit=Y`입니다. 이유는 [재현 앱 문서](POPUP_TEST_APP.md) "쿠폰·프리셋 목표·첫 통합 예상"에 있습니다. 프리셋별 목표(`preset_*` 칸)는 자동 닫기를 켠 뒤의 기준이라 첫 통합에는 쓰지 않습니다.

**P13**: 10/22 결정 거부는 재현 페이지의 시나리오 목록 글자('결제'·'동의'·'이름') 때문이었을 수 있어, 10/25부터 팝업이 떠 있는 동안 목록을 숨깁니다. 코드상 예상은 쿠폰입니다. 웹 버튼은 리소스 ID가 없어 앱 허용 버튼이 미정이므로, 누르기 버튼이 보이면 그대로 기록하고 판정은 A·B와 같이 정합니다. B 정책을 완화하는 변경이 아닙니다(A 승인 10/25). 실제 앱처럼 뒤 페이지에 위험 문구가 있는 경우의 안전 차단은 **P24**로 따로 확인합니다(예상 `USER_DECISION`/`A_SUMMARY`, 누르기 버튼 없음). 최초 빈 WebView 추출 뒤 재수집과 실제 접근성 노드 범위는 A가 실측에서 확인합니다.

P18은 A 결정 요약이 팝업 범위로 좁혀졌는지(A·B 계약 7번 연결)로 판정합니다. 첫 통합 실측은 **연결 전** 줄로 판정하고, `observed_kind`는 `USER_DECISION`(정답지 `USER_DECISION`/`A_SUMMARY`)을 기대하며 `notes`에 `영역 계약 전`이라고 적습니다. B R1 병합 여부는 P18 기대값을 바꾸지 않습니다(A가 먼저 요약하므로). 결정 버튼·질문·A 요약은 그대로입니다.

P16의 빈 영상 표면(`VideoView`, 리소스 ID `video_surface`)은 접근성 트리에 보이는지만 따로 확인합니다(`adb shell uiautomator dump` 결과에 `android.widget.VideoView`와 `video_surface`가 있는지, `docs/POPUP_TEST_APP.md` P16). 빈 표면이 보인다는 것은 영상 재생이나 영상 광고 판정의 증거가 아닙니다.

| 오래된 선택 | 팝업이 바뀐 뒤 이전 선택 창 버튼을 눌러도 새 화면에 영향 없음(A 오래된 선택 차단, C #18 콜백) | ☐통과 ☐실패 ☐못 봄 |
| TTS | 창이 뜨고 약 0.7초 뒤 1회. 반복·중첩 없음 | ☐통과 ☐실패 ☐못 봄 |
| TalkBack | 선택 창 버튼 이름·순서를 읽음, 닫힌 뒤 포커스가 앱 본문으로 돌아옴 | ☐통과 ☐실패 ☐못 봄 |

| 로그 원문 | 전체 logcat에 재현 앱 화면 문구가 없음 | ☐통과 ☐실패 ☐못 봄 |

## 8. 다음 단계: 클릭을 켠 뒤 성공 판정 (미리 정함)

첫 통합에는 클릭이 없으므로 이 절은 쓰지 않습니다. 클릭을 켜는 실측부터 아래 기준으로 판정합니다(A·C #34/#42 리뷰 10/25, `docs/F12_RULE_STORAGE.md` "누르기 성공").

**성공은 세 가지가 모두일 때만**: 누르기 시도함(`attempted`) + `MECHANICAL_SUCCESS` + 닫힘 관측(`CLOSED_CONFIRMED`).

| A 결과 | C 안내 | F12 기억 저장 | 이 칸의 실패 |
|---|---|---|---|
| 세 가지 모두 | "닫았어요" | [기억하기]를 골랐으면 1건 | 기억하기를 골랐는데 저장 0건 |
| `MECHANICAL_SUCCESS`, 닫힘 관측 없음 | "닫혔는지 확인하지 못했어요" | **0건** | "닫았어요" 안내, 또는 기억 저장 |
| `ATTEMPT_FAILED`·`OUTCOME_UNKNOWN` + `CLOSED_CONFIRMED` | "닫혔는지 확인하지 못했어요" | **0건** | "닫았어요" 안내, 또는 기억 저장 |
| `NOT_EXECUTED`·`BLOCKED`·`STALE` | 비실행 안내 | 0건 | "닫았어요" 안내 |

- 결과 CSV의 `outcome`은 지금처럼 **앱이 실제로 눌렀는지**로 적습니다(눌렀으면 `USER_CONFIRMED`/`AUTO_HANDLED`, `clicked_target` 기록). 닫힘을 확인하지 못했으면 `notes`에 `닫힘 미확인`이라고 적습니다.
- 기억 저장 건수는 설정 화면 기억 목록 개수로 확인합니다(화면 원문은 적지 않음).
- 닫힘 미확인 상황은 시험자가 일부러 만들기 어렵습니다. 관측된 경우만 기록하고, 관측하지 못한 줄은 "못 봄"으로 둡니다. 조합별 판정은 C·A JVM 시험(`PressResultSpeechTest`, `AnnouncementBatcherTest`, `PopupChoiceFlowTest`)이 맡습니다.
