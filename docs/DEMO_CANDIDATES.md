# 시연 후보 사이트·앱 20개 (D)

담당: 동준/D. 기한: 10/30 (AGENTS.md 9장). 최종 발표에서 실제로 시연할 2~3개를 고르기 위한 후보입니다. 리허설(재호·우진)에서 실제로 확인해 좁힙니다.

**상태: 후보만 정했습니다. 실기기 확인 0건입니다.** 아래 "예상 팝업"은 사이트 종류별로 흔한 팝업을 적은 **예상**이며, 실제로 뜨는지는 확인하지 않았습니다. 이벤트 팝업은 날짜·시간·로그인 여부에 따라 바뀝니다. 확인하면 정답지(`docs/templates/real_site_answer_key.csv`)의 `status`를 `OBSERVED`로, 팝업 종류·버튼을 실제 값으로 고칩니다.

## 1. 고른 기준

1. **시각장애인이 실제로 막히는 상황**: 쇼핑·배달·예매처럼 접근성 문제가 반복 보도된 분야([조사 1차](research/BLIND_USER_RESEARCH_V1.md) 3절). 특히 옥션 첫 화면 팝업 사례.
2. **팝업이 자주 뜰 만한 곳**: 앱·사이트를 열자마자 뜨는 이벤트·쿠폰 팝업, 앱 설치 유도, 전면 광고, 영상 광고.
3. **우리 앱의 차별점이 보이는 곳**: 구매 버튼과 닫기 버튼이 같이 있는 팝업(구매는 누르지 않음), 권한 요청(누르지 않음).
4. **반복 재현이 쉬운 곳**: 로그인 없이 뜨거나, 사이트 데이터를 지우면 다시 뜨는 곳(3절).

## 2. 빼는 곳

- 은행·증권·코인·간편결제 앱, 정부·의료 사이트(민감 화면, AGENTS 6-8).
- 로그인·본인 확인·결제 화면이 있어야만 팝업이 뜨는 곳.
- 성인·도박 사이트, 실제 사기 사이트(사기 의심 시연은 재현 앱 P32로 대신).
- 닫기 없이 구매·동의 버튼만 있는 팝업(누를 버튼이 없음).

## 4. 추천 순서 (D 의견)

리허설에서 A 등급부터 확인합니다. 최종 2~3개는 리허설 결과(`tools/real_site_metrics.py`의 "시연 후보" 열)로 정합니다.

1. **크롬 쇼핑 이벤트 팝업(L06 옥션 또는 L04 11번가)**: 보도된 사례와 같은 상황이고, 구매 버튼은 누르지 않고 닫기만 누르는 차별점이 보입니다.
2. **앱 시작 팝업(L14 올리브영 앱)**: 웹이 아닌 앱에서도 된다는 것을 보여 줍니다.
3. **안전 시연(L20 권한 요청 또는 재현 앱 P32 사기 의심)**: 누르지 않는 것도 기능이라는 점을 보여 줍니다.

예비: L01 네이버(팀이 예로 든 사이트), L19 유튜브(영상 광고).
