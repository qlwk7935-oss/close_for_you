# 시각장애인 스마트폰 사용 앱·상황 조사 1차 (D)

담당: 동준/D. 기한: 10/30 (AGENTS.md 9장). 최종 발표의 "왜 필요한가" 근거와 시연 사이트를 고르는 기준으로 씁니다.

**이 문서의 한계**: 공개된 기사·조사·문서만 정리한 2차 조사입니다. 당사자 인터뷰는 아직 없습니다. 오래된 자료(2018·2020년)는 연도를 밝혀 적었고, 발표에서도 연도를 같이 말해야 합니다. 수치는 각 출처가 보도한 그대로이며 원 보고서를 직접 확인하지 못한 것은 "보도 기준"이라고 적었습니다.

## 1. 발표용 세 줄 요약

1. 시각장애인 대부분이 스마트폰을 쓰지만, 쇼핑·배달 같은 생활 앱은 화면 읽기 프로그램으로 쓰기 어렵다는 조사가 반복해서 나옵니다(2절).
2. 팝업은 그중에서도 직접적인 장벽입니다. 그림으로 된 팝업은 "닫기"·"오늘 그만 보기"만 읽혀 무슨 내용인지 모르고, 닫는 데 몇 분이 걸린 사례가 보도됐습니다(3절).
3. 그래서 닫아줄게는 팝업이 뜬 것을 알려 주고, 안전한 닫기 버튼만 대신 누르며, 결제·구매·동의·권한 버튼은 누르지 않습니다(4절).

## 2. 얼마나, 무엇을 쓰나

| 내용 | 수치 | 출처·연도 |
|---|---|---|
| 시각장애인 스마트폰 이용률 | 74.2% (519명 응답) | 한국시각장애인연합회 조사, 2018 (에이블뉴스 보도) |
| 당시 사용 기종 | 삼성 36.8%, LG 23.1%, 애플 22.9% | 같은 조사, 2018. LG는 2021년 휴대폰 사업을 접었으므로 지금 비율과 다를 수 있음 |
| 전화·TV·인터넷 쇼핑을 전적으로 남에게 의지 | 40.8% | 같은 조사, 2018 |
| 모바일에서 화면 읽기 프로그램 사용(전 세계 응답자) | 91.3% | WebAIM 화면 읽기 사용자 조사 2024 (1,500여 명) |
| 같은 조사의 지역별 iOS 비율 | 북미 84%, 아시아 40% | WebAIM 2024. 아시아 응답자는 iOS가 절반 아래 |

해석(D 의견): 국내는 안드로이드 사용자가 적지 않아 TalkBack 기준으로 만드는 우리 앱의 대상이 분명합니다. 다만 국내 최신 수치는 아직 못 찾았습니다(6절 2차 조사).

## 3. 어떤 앱·상황에서 막히나

### 3-1. 생활 앱 전반

| 내용 | 수치·사례 | 출처·연도 |
|---|---|---|
| 다운로드 상위 300개 앱 접근성 평균 | 2019년 74점 → 2020년 69.2점 | 과기정통부 2020 모바일 앱 실태조사 (정보통신신문 보도, 2021) |
| 같은 조사 최하위 | 배달의민족 iOS 38.9점·안드로이드 46.2점, 쿠팡 iOS 49.0점, 야놀자 iOS 49.4점 등 | 같은 보도 |
| 보조기술 호환성 항목 | 81.2% → 54.6% | 같은 보도 |
| 2022 조사 평균 | 300개 앱 평균 75.5점. 하위에 페이코·올리브영(iOS) 등 | 과기정통부 2022 모바일 앱 실태조사 (경향신문 보도, 2023) |
| 버튼 설명이 파일 이름으로 읽힘 | 알림·마이페이지 버튼 등 | 같은 보도(페이코 사례) |
| 쇼핑·배달·동영상 앱 16개 점검 | 쇼핑앱 9개 모두 상품 상세 대체 텍스트 부족, 배달앱 결제 보안 키패드가 "버튼"으로만 읽힘 | 한국소비자원, 2024 (더나은미래 보도) |
| 같은 조사 시각장애인 193명 설문 | 정보 확인 단계 어려움 92.2%, 결제 단계 불편 88.6% | 같은 보도 |

### 3-2. 팝업·대화상자

| 내용 | 사례·근거 | 출처·연도 |
|---|---|---|
| 그림으로 된 쇼핑몰 팝업 | 옥션 첫 화면 팝업을 닫는 데 약 5분. 화면 읽기 프로그램에는 "오늘 그만 보기"와 "닫기" 두 마디만 읽힘 | 경향신문 "장애인도 소비자다", 2021 |
| 화면 읽기 사용자가 꼽은 문제 | 1위 캡차, 2위 메뉴·탭·**대화상자가 예상대로 동작하지 않음**, 3위 의미를 알 수 없는 링크·버튼, 4위 **화면이 예고 없이 바뀜** | WebAIM 2024 |
| 모달(팝업)이 주는 문제 | 팝업이 열렸는지 알기 어렵고, 초점이 팝업 밖으로 새며, 닫기 버튼을 찾으려면 여러 번 이동해야 함 | SK DevOcean 기술 블로그 |
| 방해가 되는 전면 광고·대화상자 유형 | 화면 전체를 덮는 전면 광고, 앱 설치 유도·뉴스레터 가입 같은 홍보 대화상자 | Google 검색 센터 문서 |

### 3-3. 우리 앱과 관련된 상황 정리

| 상황 | 왜 어려운가 | 근거 |
|---|---|---|
| 앱·사이트를 열자마자 뜨는 이벤트·광고 팝업 | 내용이 그림이라 무엇인지 모르고, 닫기 버튼을 찾기 어려움 | 3-2 옥션 사례, DevOcean |
| 라벨 없는 X 버튼 | "버튼"으로만 읽혀 닫기인지 모름 | 3-1 버튼 설명 문제, WebAIM 3위 |
| 연속 팝업 | 하나 닫으면 또 뜸. 화면이 예고 없이 바뀜 | WebAIM 4위 |
| 앱 설치 유도·로그인 유도 창 | 모바일 웹에서 본문을 가림 | Google 문서 |
| 결제·구매가 섞인 팝업 | 잘못 누르면 손해. 결제 단계 자체가 어려움 | 소비자원 2024 |
| 사기·경품 팝업 | 내용 확인이 어려워 속기 쉬움 | (직접 근거 없음, 2차 조사 필요) |

## 4. 닫아줄게 기능과 연결

| 문제 | 닫아줄게가 하는 일 | 지키는 안전 규칙(AGENTS 6-0) |
|---|---|---|
| 팝업이 뜬 줄 모름 | 팝업이 떴다고 말해 줌 | 화면 원문을 로그에 남기지 않음 |
| 무슨 팝업인지 모름 | 광고·쿠폰·공지·결정·사기 의심으로 나눠 안내 | 사기 의심은 누르지 않고 경고 |
| 닫기 버튼을 못 찾음 | 안전한 닫기 버튼만 대신 누름(사용자가 고른 방식대로) | 결제·구매·동의·권한·구독·삭제는 누르지 않음 |
| 매번 같은 팝업 | 같은 팝업이면 앞으로 항상 닫기(사용자 허락 뒤) | 실제로 확인한 동작만 됐다고 말함 |

## 5. 시연에 쓰면 좋은 상황 (시연 후보 선정에 반영)

1. 쇼핑 앱·사이트 첫 화면 이벤트 팝업(옥션 사례와 같은 유형): "닫기"를 찾아 대신 누르기.
2. 구매 버튼이 같이 있는 광고 팝업: 구매는 누르지 않고 닫기만 누르는 차별점.
3. 사기 의심·경품 팝업: 누르지 않고 경고(재현 앱 P32로 대신 시연 가능).

시연 후보 목록은 [`docs/DEMO_CANDIDATES.md`](../DEMO_CANDIDATES.md)에 있습니다.

## 6. 2차 조사 계획

- 국내 최신 통계: 과기정통부·NIA 디지털정보격차 실태조사, 과기정통부 모바일 앱 실태조사 최신판 원문에서 시각장애인 수치 확인.
- 팝업 직접 통계: 국내 시각장애인 대상 "팝업·광고 불편" 수치는 아직 못 찾음. 찾지 못하면 발표에서는 사례(옥션)와 WebAIM 항목으로만 말함.
- 당사자 의견: 시각장애인 단체·복지관 협조가 필요. 일정상 최종 발표 전에는 어려울 수 있음.
- 사기 팝업 피해 사례 자료.
