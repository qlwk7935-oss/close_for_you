# 팝업처리도우미

시각장애인과 저시력 사용자가 스마트폰의 광고·쿠폰·공지 팝업을 확인하고 안전하게 처리하도록 돕는 **Android 접근성 보조 앱**입니다.

팝업을 무조건 차단하는 대신, 화면의 팝업 내용과 버튼 정보를 확인하여 **안전하게 닫을 수 있는 경우에는 닫고, 판단이 필요한 경우에는 사용자에게 묻는 것**을 목표로 개발했습니다. 본 프로젝트는 대학 수업 발표를 위한 시연용 개발 결과이며, 모든 앱과 사이트에서의 동작을 보장하는 상용 제품은 아닙니다.

## 1. 제출 코드 기준

- 최종 시연 기준 브랜치: `integration/popup-helper`
- 기준 커밋: `9f777127759f0534be5e78c35a5603866f4550a2` (`9f77712`)
- F63에서 온보딩·설정·선택창의 디자인과 앱 아이콘을 정리했습니다. 팝업 처리 엔진과 안전 규칙은 이전 `e5a8c47`과 동일합니다.
- 제출용 브랜치: `submission/final-2026` (위 기준 커밋에서 **README만 최신화**했습니다. 앱 실행 코드는 동일합니다.)
- 제출본의 앱 실행 코드는 위 기준 커밋과 동일하며, 시험 결과는 README 6절의 시험 조건을 참조해 주세요.

## 2. 주요 기능

| 기능 | 동작 방식 |
| --- | --- |
| 팝업 감지·분류 | 접근성 화면 구조에서 팝업 후보와 버튼 정보를 읽고 광고·쿠폰·공지·판단이 필요한 창 등을 구분합니다. |
| 안전한 자동 닫기 | 사용자가 선택한 처리 범위에 속하고 안전 검사를 통과한 닫기 버튼만 실행합니다. 클릭 직전에 화면과 버튼을 다시 확인합니다. |
| 사용자 선택창 | 이름 없는 X 등 의미가 불확실한 버튼은 자동으로 누르지 않고 사용자에게 묻습니다. |
| 중요한 결정 보호 | 결제·구매·동의·권한 허용·삭제 등 중요한 버튼을 대신 누르지 않도록 제한합니다. 사기 의심 팝업은 경고합니다. |
| TalkBack·음성 안내 | 팝업 내용, 선택지와 처리 결과를 읽어 줍니다. 사용자가 요청하면 내용을 다시 들을 수 있습니다. |
| 음성 명령 | **Android 12(API 31) 이상**이면서 **기기 내 음성 인식을 지원하는 기기**에서만 사용할 수 있습니다. 앱의 최소 지원 OS(Android 11)와 조건이 다릅니다. |
| 방금 닫은 내용 듣기 | 닫힘 결과 카드가 표시되는 동안, 글자가 있는 팝업의 내용을 다시 들을 수 있습니다. |
| 앞으로 항상 닫기 | 사용자가 명시적으로 선택하고 첫 닫힘이 확인된 팝업에 한해, 이후 같은 내용·구조·위치·버튼을 재검사해 처리합니다. |
| 개인 설정 | 처리 범위, 도와줄 앱, 음성 관련 옵션을 직접 고를 수 있습니다. |

자동 닫기 여부는 팝업 종류뿐 아니라 현재 화면 상태, 버튼 정보, 위험 요소, 사용자의 설정에 따라 달라집니다.

## 3. 실제 시연 엔진과 개발용 엔진

최종 APK에는 접근성 서비스 두 개가 들어 있습니다.

| 접근성 서비스 | 역할 | 화면 캡처 |
| --- | --- | --- |
| **팝업처리도우미** (`SimpleCloseAccessibilityService`) | **최종 시연에 사용하는 엔진.** 접근성 노드 기반으로 팝업을 찾아 닫거나 선택창을 띄웁니다. | 사용하지 않음 |
| **닫아줄게** (`CloseForYouAccessibilityService`) | 초기 Android 코어 연구·개발용 엔진. 별도 동의를 받은 화면 캡처·한국어 OCR 경로가 포함되어 있습니다. | 별도 조건에서 가능 |

**두 접근성 서비스는 동시에 켜지 않습니다.** 최종 시연에서는 Android 접근성 설정에서 **‘팝업처리도우미’만 켜고 ‘닫아줄게’는 반드시 끕니다.** 개발용 A 엔진 화면은 앱 설정 하단의 **[개발자 화면 열기]**에서 확인할 수 있습니다.

별도의 `popup-test-app`과 `capture-test-host`는 검증을 위한 앱이며, 일반 사용 화면이나 실제 사이트 시연 결과와 구분합니다. `experiments/`는 본 앱과 별개의 실험 프로젝트입니다.

## 4. 실행 방법

1. Android 11(API 30) 이상 기기에 Debug APK를 설치하고 앱을 실행합니다.
2. 처음 설정 5단계를 진행합니다. **2단계 ‘접근성 서비스 켜기’에서 안내에 따라 Android 접근성 설정으로 이동해 ‘팝업처리도우미’를 켭니다. ‘닫아줄게’는 끄고, 두 서비스를 동시에 활성화하지 않습니다.**
3. 이어서 **3단계에서 처리 범위와 자동 닫기 동의**, **4단계에서 도와줄 앱**을 선택합니다. 5단계 요약을 확인한 뒤 [사용 시작]을 누릅니다.
4. TalkBack을 쓰는 경우 선택창과 처리 결과의 음성 안내를 확인할 수 있습니다. 음성 명령은 별도 조건(Android 12 이상 + 기기 내 음성 인식 지원)을 충족해야 합니다.

사이트마다 팝업 표시 조건과 화면 구조가 달라 같은 사이트에서도 팝업이 매번 나타나는 것은 아닙니다. 접근성 서비스는 사용자가 Android 설정에서 직접 활성화해야 합니다.

## 5. 개발·빌드 환경

- 언어 및 UI: Kotlin, Jetpack Compose
- 주요 기술: Android `AccessibilityService`, TalkBack/TTS, 기기 내 음성 인식, **Room 규칙 저장소(개발용 코어 경로)**
- **최종 시연 엔진의 팝업 기억:** Room 대신 `RememberedPopups` 기반 **별도 경량 저장소(SharedPreferences)** 사용. 팝업 식별용 해시와 버튼 위치·경로 등을 저장합니다.
- 개발용 코어 기술: 화면 캡처, ML Kit 한국어 OCR
- Android: `minSdk 30`, `compileSdk 35`, `targetSdk 35`
- 빌드: Android Gradle Plugin `8.9.2`, Kotlin `2.1.20`, Gradle Wrapper `8.11.1`
- 권장 환경: Android Studio 내장 JDK(JBR, JDK 17 또는 21 등 호환 버전), Android SDK Platform 35

Windows PowerShell에서 저장소 최상위 폴더를 열고 실행합니다.

```powershell
.\gradlew.bat :app:assembleDebug
.\gradlew.bat :app:testDebugUnitTest :capture-test-host:testDebugUnitTest :popup-test-app:testDebugUnitTest :app:lintDebug
```

Debug APK 경로: `app/build/outputs/apk/debug/app-debug.apk`

`local.properties`에 SDK 경로가 필요한 경우 Android Studio에서 설정합니다. **JDK 25는 이 프로젝트의 Gradle 8.11.1 빌드 환경에 사용하지 않습니다.** Release 빌드용 배포 서명 설정은 포함되지 않았으므로, 별도로 서명한 Release APK를 제공하는 구성은 아닙니다.

## 6. 검증 현황

**기준: `9f77712` / 팀 보고·로컬 시험 결과**

- 자동 시험 **1,615개**: 앱 Debug **1,533개** + `capture-test-host` **55개** + `popup-test-app` **27개**
- 실패 **0건**, 건너뜀 **1건**
- 앱 Release 단위 시험 **1,518개**도 실패 **0건**으로 보고됨(위 1,615개 합계와 별개)
- Lint 오류 **0건**
- 재현 앱 별도 평가에서는 **36/36개 시나리오가 정답지와 일치**, 엔진이 실제 누른 **27회 중 잘못 누른 기록 0회**였음(API 37 에뮬레이터, TalkBack 꺼짐, `e5a8c47` 엔진 기준)
- 실제 사이트 **40곳, 총 114회**를 시연용 엔진으로 시험했고, 팀 보고 기준 잘못된 버튼을 누른 사례는 **0회**였습니다. 이 숫자는 성공한 팝업 닫기 114회를 뜻하지 않으며, 사이트·기기·상황에 따라 팝업이 없거나 감지되지 않은 경우도 포함될 수 있습니다. 구체적인 시나리오별 결과는 별도 시험 기록을 참고해 주세요.
- **별도 100곳 조사(재호, LG 벨벳, TalkBack OFF):** 접속 시도 100곳 중 **접속된 사이트 95곳**, 그중 **팝업이 나타난 사이트 55곳**을 다음과 같이 기록했습니다. **사이트당 1회 시험했으며, 엔진 로그와 화면 사진을 근거로 판정했습니다.** 이 조사에서 잘못 누른 사례는 **0건**으로 보고됐습니다.

  | 팝업이 발생한 55곳의 결과 | 사이트 수 |
  | --- | ---: |
  | 닫힘 | 16 |
  | 사용자에게 물음·알림 | 9 |
  | 중요 결정 보호 | 10 |
  | 팝업 감지·처리 놓침 | 20 |

  위 **55곳의 분류 결과**는 기존 **40곳·114회 시험**과 다른 조사이며, 두 수치를 합산하거나 55곳 모두 닫혔다고 해석하지 않습니다. **TalkBack ON 조건의 100곳 조사는 하지 않았습니다. TalkBack을 켜면 자동 조작(탭·스크롤)이 실제 사용과 달라져 같은 방식으로 측정할 수 없었습니다.**
- Android 실기기에서 화면 표시와 일부 실제 사이트 동작을 확인했지만, 모든 사이트와 기기에서 검증한 결과는 아닙니다.

숫자는 정해진 시험 조건에서의 결과이며 전체 팝업에 대한 정확도 100% 또는 오작동률 0%를 의미하지 않습니다. **`integration/popup-helper` 브랜치에는 원격 CI 자동 실행이 설정되어 있지 않아**, 위 결과는 로컬 시험 기록입니다.

## 7. 권한과 개인정보 보호

- 시연용 엔진은 접근성 노드 정보를 사용하며 **스크린샷을 촬영하지 않습니다.**
- APK에서 네트워크 권한(`INTERNET`)을 제거합니다. 팝업 내용을 외부 서버로 보내는 기능은 없습니다.
- 사용자가 말하기 기능을 실행할 때 필요한 마이크 권한(`RECORD_AUDIO`)을 선언합니다. 권한은 사용자의 조작에 따라 요청하며 상시 녹음 용도가 아닙니다.
- 개발용 A 엔진의 화면 캡처·OCR은 별도 동의, 허용 앱, 민감 화면 검사 등의 조건을 거칩니다.
- **시연 엔진의 팝업 기억**은 Room이 아닌 별도 경량 저장소에 팝업 원문 대신 **식별용 해시·버튼 위치·경로** 등을 저장합니다. 개발용 코어 경로에는 별도의 Room 규칙 저장소가 있습니다. 방금 닫은 팝업의 낭독 내용은 결과 카드가 사라지면 폐기합니다.

## 8. 알려진 한계와 미검증 항목

- LMS 등 개인정보 보호 조건에 해당하는 화면은 분석 전에 중단할 수 있습니다.
- 일부 사이트의 **하단 시트**나 **‘앱으로 보기’ 유도 창** 등은 감지하지 못할 수 있습니다. LG 벨벳·TalkBack OFF의 별도 조사에서는 팝업이 나타난 **55곳 중 20곳**을 놓쳤습니다(위 6절 참고).
- 이케아 쿠키 창처럼 **페이지가 열린 뒤 늦게 나타나는 팝업**은 화면에 추가 움직임이나 이벤트가 없으면 감지하지 못할 수 있습니다.
- **그림만으로 표시한 팝업**은 그 안의 내용을 읽지 못할 수 있습니다.
- 다나와 하단 광고에서는 실제로 닫혔지만 ‘닫지 못했어요’로 안내한 사례가 있습니다. 잘못된 버튼을 누른 사례와는 구분합니다.
- 겹친 팝업에서 앞쪽 버튼을 직접 눌러 주는 실험 기능(F59)은 안전성 문제로 **최종 빌드에서 비활성화**했습니다.
- 최종 빌드 `9f77712`에서 **음성 명령의 실기기 동작은 별도로 재검증되지 않았습니다.** 음성 명령은 Android 12(API 31) 이상이며 기기 내 음성 인식을 지원해야 합니다. **LG 벨벳(Android 12)은 기기 내 음성 인식을 지원하지 않아 이 기능을 사용할 수 없었습니다.**
- 다크 모드와 시각장애인 당사자 사용성 평가는 충분히 검증되지 않았습니다.

이 저장소는 **수업 발표용 시연 결과**입니다. 실제 서비스 배포 전에는 추가 실기기 검증과 사용자 평가가 필요합니다.
