# 과잉 경고 연구 — 광고·공지가 "결정 필요"가 되는 문제

작성: B 준영 · 2026-10-22 · 시험: `DecisionOverWarningStudyTest` · **B 본 코드는 바꾸지 않았습니다(팀 결정 전 제안 자료).**

> **갱신 (2026-10-22, 우진 "R1은 별도 PR로 진행"):** R1을 `DecisionKeywords.isBenefitMention` + `hasUserDecisionSignal()`에 적용했습니다. 이제 지금 분류기가 R1과 같아서 과잉 경고 17 → 7, 위험 오류 0입니다. 분류 평가 82개에서도 과잉 경고 4 → 2, 정답 68 → 69 (`CLASSIFIER_EVAL.md` 11절). 결정 버튼·A 고정 요약·질문·처음 본 팝업 묻기·P13 거부는 그대로입니다. R2는 적용하지 않았습니다.

## 1. 문제

광고·공지 본문에 결정 단어(결제·구매·가입·구독·로그인 등)가 들어가면 B가 팝업 전체를 **결정 필요**로 봅니다. 그러면 두 가지가 틀어집니다.

- **안내가 틀립니다.** 광고인데 "결정이 필요한 팝업"이라고 안내합니다.
- **닫을 수 없습니다.** 안전 판단이 `IMPORTANT_DECISION`으로 거부해서, 사람이 '닫기'를 골라도 대신 닫지 못합니다. 결정 팝업에는 C도 누르기 버튼을 보여 주지 않습니다.

실제로 나온 사례가 있습니다.
- 분류 평가 82개 중 4개 (`CLASSIFIER_EVAL.md` 리뷰 6번)
- 에뮬레이터 재현 앱 P02 "가입하면 포인트", P18 "5초 안에 결제하면 추가 할인"

**안전한 쪽(누르지 않음)으로 틀리는 문제**이지만, 광고 닫기라는 핵심 기능을 막습니다.

## 2. 방법

- **새 평가 세트 35개를 따로 만들었습니다.** 기존 82개 세트를 보고 맞추지 않습니다.
  - 광고 12: 본문에 결정 단어가 혜택 조건으로 들어감
  - 공지 5: 결정 단어가 사실을 알리는 문장에 들어감
  - 결정 18: 진짜 결정 화면, A 고정 요약, 그리고 **광고인데 진짜 결정 버튼이 있는 함정** 5개
- 정답은 분류기를 돌리기 전에 사람이 붙였습니다. 버튼 이름도 글자로 들어갑니다. A 분석의 글자에는 클릭 가능 여부가 없기 때문입니다.
- 후보 규칙은 **시험 안에서만** 구현해서 지금 분류기와 숫자로 비교합니다.

## 3. 후보 규칙

**R1 — 혜택 조건 안의 결정 단어**

결정 단어가 들어간 글자가 **모두** 아래 조건을 만족할 때만, 그 단어를 결정 신호로 보지 않습니다.
- 조건 표현이 있음: "하면", "하고", "~ 시", "할 때", "and get", "when you", "if you"
- 혜택 단어가 있음: 할인·쿠폰·포인트·혜택·이벤트·특가·무료·증정·적립·배송, off·free·bonus·coupon
- 질문이 아님: "?", "하시겠", "할까요", "시겠어요", "필요"가 없음
- 10자를 넘는 문장임 (짧은 버튼 이름은 해당 안 됨)

그 밖에 결정 단어가 들어간 글자가 **하나라도** 있으면 지금처럼 결정입니다. 예: "구매하기" 같은 버튼, 질문, A 요약 "결제 선택 필요".

**R2 — R1 + 공지 문장 안의 결정 단어**

R1에 더해, 공지 단어(점검·공지·안내·알림·업데이트·변경)가 있는 팝업에서 결정 단어가 **사실을 알리는 문장**("~니다", "~어요")에만 있으면 결정 신호로 보지 않습니다.

## 4. 결과 (새 세트 35개)

| | 정답 | 과잉 경고 (광고·공지 → 결정) | **위험 오류 (결정 → 광고·공지)** |
|---|---|---|---|
| 지금 분류기 | 18 / 35 | **17 / 17** | 0 |
| R1 | 26 / 35 | 7 | **0** |
| R2 | 28 / 35 | 5 | **0** |

- R1·R2 모두 **결정 18개를 전부 결정으로 유지**합니다. 광고에 "구매하기"·"가입하기"·"구독"·"결제하기"·"체험 시작하기" 버튼이 있는 함정 5개도 결정으로 남습니다.
- R1이 그래도 틀리는 경우:
  - 제목 "신규 가입 이벤트"(조건 표현 없음), "Buy one get one free"(조건 표현 없음) → 여전히 결정
  - "할인"·"off"가 광고 사전에 없어서 결정 대신 **모름**이 된 2개(안전한 쪽)
- R2가 그래도 틀리는 경우: 짧은 공지 제목 "결제 수단 점검 공지", "로그인 서버 점검 공지", "개인정보 처리방침 변경 안내" → 여전히 결정
- 남은 오답은 이 세트에 맞추려고 규칙을 더 고치지 않았습니다. 고치면 이 세트가 더 이상 평가용이 아니게 됩니다.

## 5. 제안 (팀 결정 필요)

1. **R1을 먼저 적용하는 별도 PR을 제안합니다.**
   - 분류기와 안전 판단이 같이 쓰는 `hasUserDecisionSignal()`에 R1을 넣어야 안내와 "닫기 가능"이 함께 바뀝니다.
   - 시험은 이 세트로 고정합니다: 위험 오류 0, 과잉 경고 ≤ 7.
2. **그대로 유지하는 것**
   - 결정 버튼(D 등급 라벨)은 어떤 경우에도 누르지 않습니다.
   - A의 결정 고정 요약("…선택 필요")은 항상 결정입니다.
   - 처음 본 팝업은 항상 사용자에게 묻습니다.
   - A의 F0 전체 화면 보호 검사는 바뀌지 않습니다.
3. **R2(공지 문장)는 R1 실측 뒤에 따로** 논의합니다.
   - "다음 달부터 자동으로 결제됩니다" 같은 공지를 공지로 안내해도 되는지는 사용자 관점 판단이 필요합니다.
   - 공지를 닫는 것 자체는 결제를 일으키지 않지만, 안내 문구를 더 조심해야 할 수 있습니다.
4. **P13(뒤 페이지 글자)은 별도 문제입니다.** 같은 창 덮개의 팝업 영역 판단이 필요해서 이 연구와 따로 다룹니다.
