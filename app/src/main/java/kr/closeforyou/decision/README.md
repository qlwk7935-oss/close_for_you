# B — 분류·안전 판단

소유자: 준영/B, 브랜치: `feature/decision`.

`PopupClassifier`와 `ActionPolicy`를 구현하고 `ActionExecutor` 인터페이스로 A에게 실행을 요청합니다. 표시 분류와 실행 허가를 분리하고 금지 조건을 먼저 적용합니다. B가 접근성 노드를 소유하거나 직접 클릭·제스처·뒤로 가기·포커스 변경을 실행하지 않습니다.

## 구현 (JVM 단위 시험만, 실기기·런타임 미연결)

- `DecisionPopupClassifier` (F7): 결정 신호 → 근거 없음/불확실 → 트리 글자의 광고 → 공지 순 4단계. OCR 글자나 영상 표면만으로 광고라고 하지 않습니다. A가 모든 분석에 붙이는 `INCOMPLETE_EVIDENCE`는 안내가 아니라 자동화를 제한합니다.
- `DecisionActionPolicy` (F8): 금지 사유가 확인 사유보다 우선합니다. 실행 요청은 사용자가 이 화면의 검증된 닫기/건너뛰기 버튼을 고른 경우, 또는 명시적으로 반복을 허락한 정확한 규칙이 모든 조건을 만족한 경우뿐입니다. 결정 신호·오래된 화면·사용자 조작·E4·확인 안 된 E3·D/K/P/O 등급 라벨(가짜 닫기 버튼)은 금지합니다.
- `DecisionKeywords`: 설계 3-1 버튼 등급과 F7 결정 신호의 키워드 사전. 키워드 일치는 허가가 아닙니다.

앱의 런타임은 아직 `DenyAllActionPolicy`를 사용합니다. 교체는 A의 조립 위치에서 합니다.

## 팀 확인 필요

- 설계 3-3 자동 허용 조건 1(앱별 자동 닫기 켬)과 7(같은 팝업 실행 기록)은 `DecisionContext`에 정보가 없어 B가 검사하지 못합니다. 계약 추가 또는 호출 측/A 게이트 책임을 정합니다.
- 사용자의 명시 명령은 `INCOMPLETE_EVIDENCE`가 있어도 검증된 버튼에 1회 허가합니다(설계 3-5). 자동 반복은 계속 막힙니다.
- 본문의 결정 단어(예: 광고의 "구매")만으로 표시 분류가 `USER_DECISION`이 됩니다(설계 3-1의 인용 문구 주의와 비교).
- O 등급 `확인`/`OK` 버튼은 기억 규칙이 있어도 누르지 않습니다.
