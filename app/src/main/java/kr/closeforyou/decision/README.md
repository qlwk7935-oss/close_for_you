# B — 분류·안전 판단

소유자: 준영/B, 브랜치: `feature/decision`.

`PopupClassifier`와 `ActionPolicy`를 구현하고 `ActionExecutor` 인터페이스로 A에게 실행을 요청합니다. 표시 분류와 실행 허가를 분리하고 금지 조건을 먼저 적용합니다. B가 접근성 노드를 소유하거나 직접 클릭·제스처·뒤로 가기·포커스 변경을 실행하지 않습니다.

## 구현 (JVM 단위 시험만, 실기기·런타임 미연결)

- `DecisionPopupClassifier` (F7): 결정 신호 → 근거 없음/불확실 → 트리 글자의 광고 → 공지 순 4단계. OCR 글자나 영상 표면만으로 광고라고 하지 않습니다. A가 모든 분석에 붙이는 `INCOMPLETE_EVIDENCE`는 안내가 아니라 자동화를 제한합니다.
- `DecisionActionPolicy` (F8): 금지 사유가 확인 사유보다 우선합니다. 현재 실행 요청은 사용자가 이 화면의 검증된 닫기/건너뛰기 버튼을 직접 고른 경우뿐입니다. 결정 신호·오래된 화면·사용자 조작·E4·확인 안 된 E3는 금지하고, 전달받은 역할을 그대로 믿지 않고 라벨 전체가 그 역할과 일치하는지 다시 검사합니다(`CLOSE` + "닫기 전 저장", D/K/P/O 등급 라벨 금지). 기억 규칙의 자동 반복은 계약에 앱별 자동 닫기 설정과 같은 팝업 실행 기록이 추가될 때까지 꺼져 있어 항상 사용자 확인으로 갑니다(PR #8 리뷰 합의).
- `DecisionCloseCandidateFinder` (F3, E1/E2만): A의 노드 DTO에서 `DISMISS` 노드와 라벨 전체가 닫기/건너뛰기인 클릭 가능 노드를 후보로 만듭니다. "오늘 하루 닫기" 같은 K 등급은 제외하고, 글자와 설명이 다르면 제외합니다. 새 창은 활성 창 전체를 봅니다. 같은 창 덮개는 Dialog 노드가 하나일 때 그 **하위 노드**이면서 영역 안에 있는 것만 봅니다(영역이 겹치는 뒤 화면 버튼 제외). 전체 화면 전환과 `INSUFFICIENT_EVIDENCE`가 붙은 불확실한 감지는 일반 화면 이동일 수 있어 후보를 만들지 않습니다(A와 합의). OCR·아이콘(E3)·픽셀(E4)은 사용하지 않습니다.
- `DecisionKeywords`: 설계 3-1 버튼 등급과 F7 결정 신호의 키워드 사전, 후보 탐색기와 정책이 함께 쓰는 라벨 → 역할 판정. 키워드 일치는 허가가 아닙니다.

앱의 런타임은 아직 `DenyAllActionPolicy`를 사용합니다. 교체는 A의 조립 위치에서 합니다.

## 팀 합의 (PR #8 리뷰)

- 사용자의 명시 선택은 `INCOMPLETE_EVIDENCE`가 있어도 검증된 E1/E2 버튼에 1회 요청할 수 있습니다. 토큰·버튼 의미 일치, 결정·보호 차단 아님, A 게이트의 실제 화면 재검증, 최대 1회·재시도 없음이 조건입니다. `INCOMPLETE_EVIDENCE`는 A의 개인정보 차단을 무시하는 근거가 아닙니다(차단 화면은 분석 없이 `Blocked`로만 옴).
- 계약 추가 예정: 앱별 자동 닫기(기본 꺼짐, C 설정 UI), 같은 팝업 실행 기록(A 게이트, 세션 단위). 추가 전까지 자동 반복은 끕니다. D 규칙은 일치 후에도 B가 재검사하고, `STOP_ASKING`은 닫지도 다시 묻지도 않습니다.
- O 등급 `확인`/`OK` 버튼은 누르지 않습니다.
- 추후 검토: 본문의 결정 단어(예: 광고의 "구매")만으로 표시 분류가 `USER_DECISION`이 되는 문제. 표시 분류와 실행 금지를 나눠 봅니다.
