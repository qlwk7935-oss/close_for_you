# B 실기기 검증 체크리스트

작성: B 준영 · 2026-10-19 · 기준 코드: `main` `845214a`

B의 분류·후보 탐색·안전 판단은 지금까지 **합성 데이터로 만든 JVM 단위 시험**으로만 검증했습니다. 이 문서는 B가 실제 Android 환경에 대해 전제하는 것을 정리하고, 기기가 생겼을 때 **무엇을 띄워서 어떻게 확인하고, 결과에 따라 무엇을 바꿀지**를 미리 정해 둡니다.

## 2. 시험 원칙 (개인정보·안전)

- **우리가 만든 시험 화면만** 씁니다. 다른 사람의 앱, 로그인된 계정, 실제 결제·메시지 화면은 열지 않습니다(AGENTS 6-8, 검증 계획 C12 윤리).
- 기록하는 것은 **시험 화면 노드의** className, viewId 이름, 버튼 text/contentDescription, clickable·enabled, 동작(CLICK/DISMISS), 신호(NEW_WINDOW 등), B의 분류·후보·결정뿐입니다. 스크린샷·화면 원문 로그는 남기지 않습니다(AGENTS 6-9).
- 실제 클릭은 하지 않습니다. A 게이트와 실행기가 연결되기 전까지 B 결과는 **판단 결과만** 기록합니다.
- 합성 화면은 B 혼자 공용 시험 앱에 넣지 않습니다. `capture-test-host`(A 관리)나 D의 시험 앱에 추가할 때는 담당자와 먼저 합의합니다.

## 5. 결과에 따른 판단 기준

- **S4가 실제 앱 사례에서 자주 보이면 (P6 거짓):** "클릭 가능한 부모 + 라벨 있는 자식 하나" 규칙을 A와 함께 설계합니다. 조건: 자식이 정확히 하나, 그 자식 말고 다른 글자가 없음, 부모·자식 모두 팝업 소속, A 게이트도 같은 규칙으로 재검증. 라벨 계약 PR과 같이 다룹니다.
- **S6·S8에서 Dialog 노드가 없으면 (P8 거짓):** A에게 같은 창 덮개의 **팝업 영역(경계·루트 경로)을 공개 DTO로** 받는 계약을 제안합니다. B 혼자 영역을 추측하지 않습니다.
- **S8에서 `aria-label`이 contentDescription으로, `×`가 text로 오면:** 노드 단위 규칙(모든 라벨이 같은 역할)상 거부됩니다. 이 경우 text의 단독 `×`를 "장식"으로 볼지 라벨 계약에서 A·C와 정합니다. 위험 방향이므로 기본은 거부를 유지합니다.
- **S12가 흔하면:** 전체 화면 광고는 지금 합의상 후보 0개입니다. 사용자 명시 선택 경로만 열지 A와 다시 논의합니다(자동 실행은 계속 금지).
- 어떤 결과든 **위험 범주 잘못 허용 0**(라벨 계약 v1, 분류 평가)을 깨는 변경은 하지 않습니다.
